## 2. RSA 公開鍵暗号とは何か

**共通鍵暗号**では、暗号化と復号に同じ鍵を使います。そのため、相手に鍵を安全に渡す方法が問題になります。

**公開鍵暗号**では、2種類の鍵を使います。

- **公開鍵**：誰に知られてもよい。暗号化に使う。
- **秘密鍵**：本人だけが持つ。復号に使う。

誰でも公開鍵で暗号化できますが、復号できるのは秘密鍵を持つ人だけです。
**RSA**（Rivest・Shamir・Adleman、1977年）は代表的な公開鍵暗号で、「大きな数の素因数分解は難しい」ことを安全性の土台の一つにしています。

## 3. RSA の数学的基礎

| 概念 | 意味 | 関数 |
| --- | --- | --- |
| 素数 | 1 と自分自身以外に約数を持たない 2 以上の整数 | `number_theory.is_prime(n)`（試し割り法） |
| 最大公約数 | 2つの整数の共通の約数のうち最大のもの | `number_theory.gcd(a, b)`（**教科書の関数**） |
| 互いに素 | 最大公約数が 1 | `number_theory.is_coprime(a, b)` |
| 合同式 | a ≡ b (mod m)：a と b を m で割った余りが等しい | — |
| モジュラ逆元 | a × x ≡ 1 (mod m) を満たす x | `number_theory.mod_inverse(a, m)` |
| オイラーの φ 関数 | 1〜n のうち n と互いに素な数の個数。異なる素数 p, q について φ(pq) = (p−1)(q−1) | `rsa.totient(p, q)` |

### ユークリッドの互除法

gcd(x, y) = gcd(y, x mod y) を、y が 0 になるまで繰り返します（教科書 第5章 `gcd.py` の再帰版）。

```text
gcd(3120, 17) = gcd(17, 9) = gcd(9, 8) = gcd(8, 1) = gcd(1, 0) = 1
```

### モジュラ逆元が存在する条件

a × x ≡ 1 (mod m) を満たす x が存在するのは、**a と m が互いに素（gcd(a, m) = 1）のときだけ**です。
例えば 6 と 3120 は公約数 6 を持つので、6 × x を 3120 で割った余りは必ず 6 の倍数になり、1 にはなりません。

Core Research では、逆元を Python 標準の `pow(a, -1, m)` で求めています（Python 3.8 以降）。拡張ユークリッド互除法による計算は Advanced B の課題です。

## 4. 鍵生成の仕組み（`rsa.generate_keys(p, q, e)`）

| 手順 | 内容 | 例 |
| --- | --- | --- |
| 1 | 異なる2つの素数 p, q を選ぶ | p = 61, q = 53 |
| 2 | n = p × q | n = 3233 |
| 3 | φ(n) = (p − 1)(q − 1) | φ(n) = 60 × 52 = 3120 |
| 4 | 1 < e < φ(n) で、gcd(e, φ(n)) = 1 となる公開指数 e を選ぶ | e = 17 |
| 5 | e × d ≡ 1 (mod φ(n)) を満たす秘密指数 d を求める | d = 2753（17 × 2753 = 46801 = 15 × 3120 + 1） |
| 6 | 公開鍵 (n, e)、秘密鍵 (n, d) | (3233, 17)、(3233, 2753) |

`generate_keys()` は次の入力を検証し、不正な場合は `ValueError` を送出します。

- p と q が素数であること、p ≠ q であること
- 1 < e < φ(n) であること
- gcd(e, φ(n)) = 1 であること（＝逆元 d が存在すること）

## 5. 暗号化と復号

メッセージ m は **0 以上 n 未満の整数**とします（文字列は扱いません）。

| | 式 | 関数 | 例 |
| --- | --- | --- | --- |
| 暗号化 | c = m^e mod n | `rsa.encrypt(m, public_key)` | 65^17 mod 3233 = **2790** |
| 復号 | m = c^d mod n | `rsa.decrypt(c, private_key)` | 2790^2753 mod 3233 = **65** |

e × d ≡ 1 (mod φ(n)) なので、(m^e)^d = m^(ed) ≡ m (mod n) となり、元に戻ります（オイラーの定理による）。

`encrypt()` と `decrypt()` は、引数 `power` で剰余べき乗の計算方法を選べます。

```python
rsa.encrypt(65, public_key)                               # 繰返し二乗法（既定）
rsa.encrypt(65, public_key, power=modular_power_naive)    # 通常の反復乗算
rsa.encrypt(65, public_key, power=pow)                    # Python 標準の pow
```

## 6. 通常の反復乗算（`modular_power_naive`）

base を exponent 回掛けます。**掛けるたびに modulus で割った余りを取る**のがポイントです。
先に base ** exponent を計算すると、途中の整数が巨大になってしまいます（2790^2753 は約9500桁）。

```python
result = 1 % modulus          # modulus = 1 のとき答えを 0 にするため、1 ではなく 1 % modulus
for _ in range(exponent):
    result = (result * base) % modulus
```

- 剰余乗算の回数：**exponent 回**
- 指数が大きすぎると終わらないので、安全のため `MAX_NAIVE_EXPONENT`（1,000万）を超える指数は `ValueError` にしています。

## 7. 繰返し二乗法（`modular_power_squaring`）

指数を2進数で考えます。例えば 3^13 は、13 = 2進数 `1101` なので、

```text
3^13 = 3^8 × 3^4 × 3^1
```

底を 3 → 3² → 3⁴ → 3⁸ と**二乗しながら**、指数の2進数の 1 の桁に当たるものだけを結果に掛けます。

```python
result = 1 % modulus
base = base % modulus
while exponent > 0:
    if exponent % 2 == 1:                   # 奇数：今の底を結果に掛ける
        result = (result * base) % modulus
    base = (base * base) % modulus          # 底を二乗する
    exponent = exponent // 2                # 指数を半分にする
```

この実装の剰余乗算の回数は、「指数のビット長（二乗の回数）」＋「指数の2進数の 1 の個数」です。

| 指数 | 2進数 | ビット長 | 反復乗算 | 繰返し二乗法 |
| ---: | --- | ---: | ---: | ---: |
| 17（e） | 10001 | 5 | 17回 | 5 + 2 = 7回 |
| 2,753（d） | 101011000001 | 12 | 2,753回 | 12 + 5 = 17回 |
| 100,000 | 11000011010100000 | 17 | 100,000回 | 17 + 6 = 23回 |
| 1,000,000 | 11110100001001000000 | 20 | 1,000,000回 | 20 + 7 = 27回 |

（最後の二乗は結果に使われないので、1回減らす実装も可能です。何を数えたか明記しましょう。）

## 8. 理論計算量の比較

指数の**数値**を e とします。

| 方法 | 剰余乗算の回数 | 計算量 |
| --- | --- | --- |
| 通常の反復乗算 | e 回 | **O(e)** |
| 繰返し二乗法 | 約 log₂e 〜 2 log₂e 回 | **O(log e)** |
| Python 標準の `pow` | 繰返し二乗法系の方法（C 言語で実装） | O(log e) |

- e が2倍になると、反復乗算の回数は2倍、繰返し二乗法の回数は**1〜2回増えるだけ**です。
- 指数の**数値** e と、**ビット長** k = ⌊log₂e⌋ + 1 を区別してください。O(log e) = O(k) なので、繰返し二乗法はビット長に比例し、反復乗算は**ビット長に対して指数的（O(2^k)）**です。RSA の d は n と同程度のビット長（実用では2048ビット以上）なので、反復乗算では現実的に計算できません。

> ⚠️ これらは、**1回の剰余乗算を一定時間とみなす単純化したモデル**による評価です。
> 実際には、整数が大きくなると1回の乗算・剰余にかかる時間も増えます（modulus のビット長を k とすると、筆算方式の乗算は O(k²)）。大整数のビット長を考慮した計算量は、Advanced A・C で扱います。

## 13. Advanced Research：発展課題

必須課題を終えたチームが挑戦する課題です。**Advanced A〜E のうち、チームの能力と時間に応じて1つ以上を選択**してください。すべてを実装する必要はありません。

### Advanced A：繰返し二乗法の計算量を実験で検証する

**目的**：O(e) と O(log e) の違いを定量的に確認する。

1. 指数 e を段階的に増やす（例：10, 100, 1,000, …、または 2倍ずつ）。
2. 通常の反復乗算の演算回数を測定する。
3. 繰返し二乗法の演算回数を測定する。
4. 実行時間を比較する。
5. 指数の数値とビット長の関係を分析する。
6. 理論計算量と実測結果を比較する。

**特に、e が2倍になったときに演算回数がどう変わるか**を調べてください。発展的には、modulus を大きくして「1回の乗算のコスト」が増える様子も調べます。

### Advanced B：ユークリッド互除法と拡張ユークリッド互除法

**目的**：RSA の鍵生成に必要な整数論アルゴリズムを理解する。

1. ユークリッド互除法を理解する（教科書 `gcd.py`）。
2. **再帰版と反復版**を比較する（反復版を自分たちで書く。教科書 第5章の再帰と非再帰の考え方を参考に）。
3. **拡張ユークリッド互除法**を実装する（`number_theory.extended_gcd` の TODO）。
4. モジュラ逆元を計算する。
5. Python 標準の `pow(e, -1, phi)` による逆元計算と結果を比較する。
6. 入力整数のビット長と計算時間を分析する（ユークリッドの互除法の繰り返し回数は、入力の桁数に比例する程度で済むことが知られている：ラメの定理）。

### Advanced C：鍵長と RSA の計算コスト

**目的**：鍵の大きさが暗号化・復号の計算時間に与える影響を調べる。

1. 異なる大きさの素数を用意する（`is_prime()` で確認できる範囲、または Advanced D の方法で）。
2. n のビット長（`n.bit_length()`）を計算する。
3. 公開指数 e と秘密指数 d の大きさを比較する（e は小さく選べるが、d は n と同程度の大きさになることが多い）。
4. 暗号化と復号の処理時間を比較する。
5. 通常の反復乗算と繰返し二乗法の**実行可能性**を比較する（d が何ビットになると反復乗算では終わらなくなるか）。
6. 大整数の乗算コストを調査する（筆算方式 O(k²)、Karatsuba 法 など）。

> 安全な実用鍵を生成することは目的としません。**ローカルの小規模な数値実験**として行ってください。

### Advanced D：素数判定と鍵生成アルゴリズム

**目的**：RSA の鍵生成における素数判定の重要性を理解する。

1. 試し割り法による素数判定（`is_prime()`）を読み、教科書 第2章の工夫を取り入れて改良する。
2. 素数候補の大きさを変更する。
3. 素数判定の処理時間を測定する。
4. **Miller–Rabin 素数判定法**を調査する。
5. 試し割り法と確率的素数判定法を比較する（実装は任意）。
6. 鍵生成の計算コストを考察する。

> 試し割り法は √n まで調べるので、n のビット長 k に対して約 2^(k/2) 回の除算が必要です（ビット長に対して指数的）。実用の RSA は 1024 ビット以上の素数を使うため、試し割り法では判定できません。
> 教材用の小さな素数と、実用暗号に必要な素数生成（十分な大きさ、暗号学的に安全な乱数、確率的素数判定）は**まったく別物**です。

### Advanced E：RSA の安全性と計算困難性

**目的**：RSA の数学的な仕組みと、実用的な暗号の安全性の違いを理解する。

1. 小さな n の素因数分解を試す（例：3233 = 61 × 53 を試し割りで求める）。
2. n の大きさと素因数分解の計算量を調べる。
3. 公開鍵から秘密鍵を計算することが、なぜ小さな教材例では容易なのかを考察する（n を分解できれば φ(n) と d がすぐ求まる）。
4. 鍵長と安全性の関係を調査する。
5. **RSA-OAEP などのパディングの必要性**を調べる。
6. 実用 RSA では**信頼できる暗号ライブラリ**が必要な理由を説明する。

> ⚠️ **小さな教材用の整数だけ**を対象にしてください。実在の鍵や第三者の暗号データを対象にしてはいけません。
> RSA の安全性を「素因数分解が難しいから安全」とだけ説明せず、**鍵長・パディング・実装上の問題**などを含めて考察してください（15章）。

## 14. 実験条件と評価指標

### 記録すべき実験条件

- PC 環境（CPU、メモリ）、OS、Python のバージョン
- base、exponent（数値とビット長）、modulus（数値とビット長）
- 使った素数 p, q、公開指数 e、秘密指数 d
- 測定回数と、平均値・中央値などの集計方法

### 評価指標

| 指標 | 内容 |
| --- | --- |
| 結果の一致 | 3つの方法の結果が同じか（必ず確認する） |
| 剰余乗算の回数 | 何を1回と数えたかを明記する |
| 処理時間 | 測りたい処理だけを `time.perf_counter()` で挟む |
| 指数の数値とビット長 | `exponent`、`exponent.bit_length()` |
| modulus のビット長 | `n.bit_length()` |

### 注意

- **同じ base・exponent・modulus** を使い、すべての方法の**結果が一致すること**を確認する。
- 反復乗算は指数の数値に比例して遅くなります。**指数を大きくしすぎない**でください（`MAX_NAIVE_EXPONENT` を超えると止まります）。
- **指数の数値とビット長**を区別する。
- **実行時間の比較と演算回数の比較**を区別する。
- Python 標準の `pow` は C 言語で実装・最適化されています。Python で書いた関数との時間差には、**アルゴリズムの違いだけでなく実装言語の違い**も含まれます。

## 15. RSA の安全性と教材上の制限

このリポジトリの RSA は「**教科書的な RSA（textbook RSA）**」であり、次の理由から**実用には使えません**。

| 問題 | 内容 |
| --- | --- |
| 鍵が小さすぎる | n = 3233 は一瞬で素因数分解でき、秘密鍵 d がすぐ求まる。実用では 2048 ビット以上の n が推奨されている（NIST SP 800-57） |
| パディングがない | 同じメッセージは常に同じ暗号文になる（推測したメッセージを暗号化して比べれば、中身が分かる） |
| 準同型性 | 暗号文どうしを掛けると、平文どうしを掛けたものの暗号文になる（E(a) × E(b) mod n = E(a × b mod n)）。暗号文を改ざんして意味のある変化を起こせる |
| 特別なメッセージ | 0, 1, n − 1 は暗号化しても（e が奇数なら）自分自身になる |
| 実装上の問題 | 繰返し二乗法は、指数のビットが 1 か 0 かで処理時間が変わる。処理時間から秘密指数 d を推測される**サイドチャネル攻撃**の原因になり得る。実用ライブラリは、こうした対策（定数時間の実装など）をしている |
| 素数の生成 | 実用では、暗号学的に安全な乱数で十分大きな素数を生成する必要がある |

実用 RSA では、**RSA-OAEP**（暗号化）や **RSA-PSS**（署名）などのパディング方式を使い、鍵生成・パディング・定数時間の実装などを備えた**信頼できる暗号ライブラリ**を使います。**自作した RSA を実際の秘密情報の保護に使ってはいけません。**

# 教員向けガイド（C-1 Cybersecurity Programming Starter）

**教員専用の文書です。学生には配布しません。**
学生向けの説明は Notebook、`README.md`、`TASKS.md`、`data/README.md` にあります。

## 1. 教材のねらい

サイバーセキュリティを題材に、Python の基本（for・if・関数・リスト・辞書・集合・文字列・CSV）と、
「同じ結果をより速く求める」「判定のしかたを変える」という 2 種類の改良を学ぶ演習です。
セキュリティの専門知識は前提にしません。検出結果は常に「調べる必要がある候補」と表現させてください。

## 2. Level の位置づけ

| Level | 位置づけ | 範囲 | 完成したときにできること |
| --- | --- | --- | --- |
| Level 1 | 必須 | STEP 1〜3（各テーマ 4 関数） | データを読む → 数える・集計する → 閾値で候補を出す、基本的な監視プログラム |
| Level 2 | 推奨 | STEP 4（各テーマ 2〜3 関数） | 効率化（辞書・集合）と検出方法の改良。基本版との比較 |
| Level 3 | 選択 | STEP 5 | 公開ログへの適用、時間窓、評価指標など |

Level 2 の課題には「改良の種類」を明記しています。

- **効率化**：結果は基本版と同じ。`compare_speed` で、一致を確かめてから時間を比べる。
- **検出方法の改良**：結果は変わってよい。ラベルを使った評価や、見つかったものの違いで比べる。

## 3. テーマ別の学習目標と指導のポイント

| テーマ | 学習目標 | つまずきやすい箇所 | 指導のポイント |
| --- | --- | --- | --- |
| C-1A | 回数を数える、重複のない一覧、辞書・集合 | 課題3 の重複のない一覧（`not in`）、タプルの分解、`>=` と `>` | 「通信回数」は**記録の件数**（フロー数）であって、パケット数ではない。回数が多い ≠ 攻撃（更新やバックアップ） |
| C-1B | 2 つの条件（`and`）、0 回のユーザーも含める集計、集計の切り口 | 課題3 で失敗 0 回のユーザーを落とす | **認証の失敗 ≠ 不正認証**。不正なログインは「成功」として記録される。`result` は正解ラベルではない |
| C-1C | 文字列（`len`、`in`）、早期 return、`or`、ルールの設計 | 課題3 で `return False` を for 文の中に書く | 攻撃の文字列は実行しない・送信しない。改良は速さではなく「何を見つけるか」。Level 2 が長い URL を見逃すことも教材として扱う |
| C-1D | 線形探索、差分、集合、ハッシュ値の辞書 | 課題1 の早期 return、課題4 の `kept` | **名前が同じ ≠ 中身が同じ**。H001 などは疑似ハッシュ。実際のファイルは変更しない |
| C-1E | 合計（`+=`）、辞書、通信先別の集計 | CSV の数値が文字列のまま（`load_csv` の `int_columns` で対応済み） | **送信量が多い ≠ 情報流出**（バックアップの例 `192.0.2.44`）。C-1A は回数、C-1E は量 |

### 全テーマ共通のつまずき

- 第1章と 3.7・3.8 の共通関数を実行しないまま、担当章に進む（`NameError`）。→ 0.5 の学習ルートを最初に確認させる。
- `[エラー]` を `[未実装]` と混同する。→ `[エラー]` は「場所」に表示された行を見る。
- Notebook を開き直した後に、上のセルを実行し忘れる。

## 4. 参照実装（完成解答）の使い方

- 場所：`solutions/reference_solutions.py`（**Git 管理外**。学生に配布しない。バックアップは教員の責任で別に保管する）
- 全 33 関数（Level 1：20、Level 2：13）を、基本文法だけで書いています。別解は多数あります。
- 検証：

```bash
cd c1-web-attack-detection
.venv/bin/python scripts/run_reference_check.py
```

  配布用 Notebook は書き換えず、メモリ上のコピーに参照実装を差し込んで実行し、第4〜8章の動作確認がすべて `[OK]` か確かめます。
  実行結果を目で確かめたいときは `--save results/reference_run.ipynb`（`results/` は Git 管理外。**解答を含むので配布しない**）。

## 5. テストの実行方法

```bash
cd c1-web-attack-detection
.venv/bin/python -m unittest discover -s tests -t .    # 教員環境：全テスト
python3 -m unittest discover -s tests                   # nbformat がない環境：実行系のテストはスキップ
python3 scripts/validate_datasets.py                    # データ品質の検証
```

主なテスト：Notebook の構造・生成・上書き防止、未実装のままの一括実行、テーマ別の独立実行、Small Dataset がない場合、
共通関数（未実装・エラー・不一致の区別）、前処理の再現性、参照実装による全課題の検証、解答の混入防止。

## 6. Notebook の更新方法

- 教材を直すときは `scripts/build_notebook.py` を編集し、`.venv/bin/python scripts/build_notebook.py` で再生成する。
- 生成した Notebook には、セルの内容の指紋（`metadata.c1_generator`）が入っています。
  **実行結果がある、または生成後に内容が編集された Notebook には上書きしません**（学生の Notebook を守るため）。
  別のファイルに出すときは `--output`、上書きしてよいときだけ `--force`。
- Tiny Dataset を作り直した場合は、`build_notebook.py` の Tiny の期待値も見直し、`run_reference_check.py` で確認する。

## 7. 成果物の評価の目安

| 観点 | Level 1（合格の条件） | Level 2（加点） | Level 3（加点） |

| 動作 | Level 1 の動作確認が Mini・Tiny とも `[OK]` | Level 2 の動作確認が `[OK]` | 公開ログ・評価などが動く |
| 説明 | 処理の流れを自分の言葉で説明できる | 計算量（O(N) と O(NK) など）を説明できる | 方法の限界を説明できる |
| 考察 | 閾値を変えたときの変化、誤検出の例 | 効率化と検出方法の改良を区別して比べている | 評価の単位・ラベルの有無を正しく扱っている |
| 表現 | 「候補」と表現し、攻撃と断定しない | 実測値と環境の違いに触れている | 人工データの結果を実環境の性能と混同しない |
| チーム | 全員が少なくとも 1 つの関数を実装 | Git のコミット履歴で分担が分かる | |

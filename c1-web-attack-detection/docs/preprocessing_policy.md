# データ前処理方針（Phase 2 以降に適用）

## 1. 基本原則

1. **再現性**：前処理はすべて `scripts/preprocess_c1x.py` で行い、手作業の編集をしない。乱数はシード固定。
2. **原データの保護**：原データは `data/raw/<データ名>/` に置き、Git で管理しない。前処理は原データを書き換えない。
3. **捏造しない**：原データにない情報を作らない。派生特徴量を作る場合は計算方法を `data_dictionary.md` に記録する。
4. **学生の課題を奪わない**：集計結果・異常度・URL の長さなど、学生が計算する値は前処理で計算しない。
5. **最小限の列**：必要な列だけを残す。教材管理用の ID（`record_id`）と原データの情報を区別する。

## 2. 処理の手順（各スクリプト共通）

| 順番 | 処理 | 注意 |
| --- | --- | --- |
| 1 | 原データの存在とチェックサムの確認 | チェックサムを `dataset_sources.md` に記録 |
| 2 | 必要列の抽出、カラム名の統一 | `data_dictionary.md` のカラム名に合わせる |
| 3 | データ型の変換、UTF-8 への統一 | 改行コードは LF |
| 4 | 欠損値の処理 | 削除した件数を記録。欠損を勝手に埋めない |
| 5 | 重複の処理 | 完全重複のみ削除し、件数を記録 |
| 6 | タイムスタンプの統一 | ISO 8601。年がない場合（Loghub）は仮の年を付けたことを明記 |
| 7 | 匿名化 | 下記 4 章 |
| 8 | 縮小（件数を減らす） | 下記 3 章 |
| 9 | ラベルの整理 | 下記 5 章 |
| 10 | 品質検証 | `validate_datasets.py` に仕様を追加し、結果を `preprocessing_report.md` に記録 |

## 3. 時系列構造の保持と縮小

- 時系列分析に使うデータは、**連続した時間区間**を切り出す（ランダムサンプリングで時間の連続性を壊さない）。
- 複数の区間を結合する場合は `segment_id` 列を追加し、区間をまたいで時間窓を集計しないよう Notebook で注意する。
- 時間情報は、基本課題で使わなくても可能な限り残す。

## 4. 匿名化と秘密情報

- IP アドレス・ユーザー名・ホスト名・ファイルパスは、必要に応じて一貫した匿名 ID に変換する（同じ値 → 同じ ID）。
  - 例：外部 IP → `ext-001`、内部 IP → `host-001`。対応表は `data/raw/`（Git 管理外）にのみ保存する。
- 攻撃者が試したユーザー名（`root`、`admin` など）は個人を特定しないため、そのまま残してよい。実在の個人名らしいものは匿名化する。
- パスワード、API キー、セッショントークン、Cookie などの秘密情報は**削除**する（HTTP データでは特に注意）。

## 5. ラベル

- 正解ラベルがない場合は `label = unknown` とし、**正常（benign）に置き換えない**。
- CIC-IDS2017 の攻撃ラベルを、C-1E の「情報流出」の正解として使わない。
- 教育用に正常・異常の比率を調整した場合は、原データの比率と調整後の比率の両方を記録し、実環境の攻撃発生率ではないことを明記する。
- 閾値調整用と評価用のデータを、可能な範囲で分ける（例：前半の時間区間で調整、後半で評価）。

## 6. 公開データの不足を人工データで補う場合

別ファイル（例：`http_requests_synthetic_small.csv`）にし、ファイル名と README で人工データであることを明示する。公開データと混ぜない。

## 7. 安全性

- 攻撃に似た文字列は文字列のまま保存し、評価・実行しない。
- CSV のセルが `=`、`+`、`-`、`@` で始まる場合、表計算ソフトで数式として解釈されるおそれがある。検証スクリプトで検出し、必要なら先頭にスペースを付けるなどの対処をして記録する（原データの値を変えたことを明記）。

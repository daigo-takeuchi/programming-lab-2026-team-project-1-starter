# プロジェクト仕様書：C-1 Cybersecurity Programming Starter

この文書は、教員から受け取った開発指示（全 Phase 共通の仕様）を要約したものである。開発時の詳細な判断基準として使う。

## 1. 名称と範囲

- 名称：C-1：サイバー攻撃の検出 ― ネットワーク・Web・API・システムを対象としたセキュリティ監視システムの開発 ―（C-1 Cybersecurity Programming Starter）
- 作業ディレクトリ：既存の `c1-web-attack-detection`（名称変更しない）
- メイン Notebook：`C1_cybersecurity_starter.ipynb`（C-1A〜C-1E を統合）
- 対象外：C-1F（外部サービスの侵害と被害波及リスク。C-2 と重複）

## 2. 対象学生と教育目標

- AI・情報系専門学校のプログラミング演習Ⅰ。Python の基本文法は学習済み。セキュリティ・ネットワーク・Linux・HTTP・データ分析・計算量・Git の経験は少ない。留学生を含む。
- 学ぶこと：変数、条件分岐、for/while、関数、リスト、辞書、集合、文字列処理、ファイル入出力、CSV、探索・集計・比較、閾値判定、基本的な時系列処理、アルゴリズムの改良、計算量の基礎、実行時間の比較、テストとデバッグ、Git によるチーム開発。
- 主要な処理は標準ライブラリで実装させる。pandas・NumPy・matplotlib は前処理・確認・可視化のみ。
- OOP・SOLID・DB・Web アプリ・機械学習・CI/CD などは上位科目（演習Ⅱ・総合演習）に回す。

## 3. 教材の難易度設計

### 5 ステップ（全テーマ共通）

| STEP | 内容 | レベル |
| --- | --- | --- |
| 1 | データを見て理解する（教員提供コードを実行、手で確認） | Level 1 |
| 2 | 数える・探す・比較する（for と if で小さな処理） | Level 1 |
| 3 | 異常を検出する（閾値、候補の抽出。候補 ≠ 攻撃） | Level 1 |
| 4 | アルゴリズムを改良する（辞書・集合、出力の一致確認、実行時間、計算量） | Level 2 |
| 5 | 実データで評価・発展させる（公開データ、時間窓、誤検出・検出漏れ、独自機能） | Level 3 |

### 課題設計の基準

- Level 1 は 1 テーマ 3〜5 個の小課題。1 関数は数行〜15 行程度。基本アルゴリズムも学生が実装する。
- 各課題に：何を・なぜ・入力・期待出力・具体例・ヒント（3 段階：考え方／文法／疑似コード）・動作確認方法。
- 配布用 Notebook に完成解答を含めない。

## 5. データ方針（B：教育用簡略版）

| 種類 | 件数 | 形式 | 由来 | 用途 |
| --- | --- | --- | --- | --- |
| Mini | 5〜10 | Notebook 内のリスト・辞書 | 人工 | STEP 1〜3 の導入、手計算での確認 |
| Tiny | 20〜50 | CSV | 人工 | 基本課題、テスト、デバッグ。正常・異常・境界を含む |
| Small | 500〜5,000（目安） | CSV | 公開データを教員が前処理 | 実データへの適用 |
| Benchmark | 1,000〜100,000 | 必要時に生成 | 人工（シード固定） | 実行時間・計算量の比較 |

- 基本課題は公開データなしで完了できる。Small がなくてもエラーで止まらない。
- 公開データの準備は Phase 2A（Loghub・既存データ、完了）と Phase 2B（CIC-IDS2017、保留）に分ける。**Phase 2B は Phase 3・4・5 の開始条件にしない。**
- Loghub 由来のデータは授業内の限定利用にとどめ、公開 GitHub リポジトリには含めない（教員の方針）。
- C-1C は CSIC HTTP 2010 を保留し、人工データ（Tiny と旧教材のアクセスログ）で Level 3 まで進められるようにする。
- 実運用の公開ログ／研究用の公開データ／加工データ／人工テストデータ／人工ベンチマークデータを区別する。
- 原データにない情報を捏造しない。未知ラベルを正常にしない。学生が計算すべき値を前処理で計算しない。
- 再配布条件が不明確なデータは学生配布物に入れない。

## 6. Notebook の構成

第0章 目的と進め方／第1章 実行環境／第2章 データセット／第3章 Python の基本と共通関数／第4〜8章 C-1A〜C-1E（各 N.1〜N.10）／第9章 性能評価とチーム開発。

- 各テーマの章は第0〜3章だけに依存し、他テーマの変数・関数・データを使わない。
- 未実装の関数があっても一括実行で止まらない（`check()` が `NotImplementedError` のみ捕捉）。
- 日本語表記方針：読む部分は日本語、プログラムとして扱う部分は英語。初出の専門用語は日英併記。
- 日本語フォントがない環境では、グラフ内のみ英語表記に切り替える。

## 7. 評価方針

- Level 2 の改良は 2 種類に分けて明記する：**効率化**（同じ結果をより速く。`compare_speed` で一致を確認してから計測）と、**検出方法の改良**（結果が変わってよい。ラベルを使った評価や見つかったものの違いで比べる）。

- 計算効率の改善（同じ出力をより速く）と、判定ルールの改善（別の検出アルゴリズム）を区別する。
- 計算量：O(1)、O(N)、O(N²)、O(NK)。辞書・集合の平均 O(1) の仮定を明示する。
- 実行時間：`time.perf_counter()`、複数回の中央値。読み込み・生成・実行・表示の時間を分ける。
- 検出性能（TP/FP/TN/FN、Accuracy、Precision、Recall、F1、FPR）は正解ラベルがある場合のみ。評価単位をそろえる。ラベルを検出の入力にしない。ラベルがない実データでは指標を計算しない。

## 8. 実行環境・制約

- Windows / WSL2 / VS Code Jupyter / Jupyter Notebook / Google Colab、Python 3.11〜3.13。
- pathlib、相対パス。PC 固有の絶対パスを Notebook に書かない。
- 500MB 超の個別ファイル、合計 2GB 超、PCAP、大規模な依存パッケージは事前に教員の承認を得る。学生配布物は 10〜20MB 程度。
- Git：既存リポジトリを継続使用。push・マージ・履歴の書き換え・リモート変更などは承認なしに行わない。

## 9. 安全性と倫理

オフライン分析のみ。実ネットワークのスキャン、攻撃リクエストの送信、不正認証、マルウェアの実行、ファイルの破壊・暗号化、設定の不正変更、情報の持ち出しは実装しない。データ内の不審な文字列は安全なテキストとして扱う。CSV の数式実行リスク（`=`、`+`、`-`、`@` で始まるセル）を検証スクリプトで確認する。

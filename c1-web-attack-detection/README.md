## 1. 研究テーマと目的

**C1：Webサーバーへのサイバー攻撃の検出**

Web サーバーのアクセスログを解析し、**特定の IP アドレスからのアクセス集中**や**大量の 404 エラー**を検出します。
研究の中心は、**線形探索と Python の辞書による集計アルゴリズムの比較**です。

| | 問い |
| --- | --- |
| RQ1 | **ログから異常をどう検出するか**：IP 別のアクセス回数・404 エラー回数・404 エラー率、異常判定の閾値、正常と異常の違い |
| RQ2 | **集計アルゴリズムの性能差**：リストの線形探索と辞書の集計で、ログ件数 N・異なる IP 数 U に対する処理時間とメモリ使用量はどう違うか |
| RQ3 | **検出精度と誤検知**：閾値を変えるとどうなるか、正常なアクセス集中を誤検知する可能性、404 が攻撃とは限らない理由、時間窓の必要性 |

学習段階に応じて、課題を2層に分けています。

- **Core Research（必須課題）**：ログの読み込み、2つの方法による集計と比較、固定閾値による検出、N・U を変えた性能比較
- **Advanced Research（発展課題）**：時間窓、404 のパターン分析、動的閾値と誤検知の評価、大量ログの高速処理

このリポジトリは**完成済みの異常検知システムではありません**。基本的な集計と固定閾値の検出だけを用意しています。

## 2. Web アクセスログとは何か

Web サーバーは、受け取ったリクエスト（ページの閲覧など）を1件ずつ**アクセスログ**に記録します。
1行に1件、次のような情報が書かれています。

- **誰から**：アクセス元の IP アドレス
- **いつ**：日時
- **何を**：HTTP メソッド（GET、POST など）と URL のパス
- **結果**：ステータスコード（200 = 成功、404 = 見つからない など）と、送信したデータのサイズ

アクセスログは、障害の調査、利用状況の分析、そして**不審なアクセスの発見（セキュリティ監視）**に使われます。

## 3. アクセス集中と 404 エラー

### アクセス集中

特定の IP アドレスから短時間に大量のアクセスがあると、サーバーに負荷がかかります。
サービス妨害を狙ったアクセスや、情報を自動で大量に集めるプログラム（クローラ）などが考えられます。

### 404 エラーの集中

404 は「要求されたページが存在しない」という意味です。
特定の IP アドレスから、存在しない URL へのアクセスが続く場合、**管理画面や設定ファイルなどの場所を探している（探索行動）**可能性があります。

### ただし、どちらも「攻撃」とは限らない

- **正常なアクセス集中**：セールやニュースで人が集まる、検索エンジンのクローラ、社内の多数の利用者が1つの IP アドレス（NAT・プロキシ）を共有している、など。
- **正常な 404**：古いブックマーク、リンク切れ、URL の打ち間違い、ブラウザが自動で取りに行くファイル（`favicon.ico` など）。

そのため、この教材では検出結果を「**アクセス集中を検出**」「**404エラー集中を検出**」「**調査が必要なIP**」と表現し、「攻撃者を特定した」「攻撃を確定した」とは言いません（8章）。

## 4. ログデータの形式

### 形式

Apache の Common Log Format に近い形式です（`log_parser.py` の `LOG_PATTERN`）。

```text
IPアドレス - - [日/月/年:時:分:秒 タイムゾーン] "メソッド パス プロトコル" ステータスコード サイズ
192.0.2.10 - - [15/Nov/2026:10:00:05 +0900] "GET /index.html HTTP/1.1" 200 2048
```

- ファイルの文字コードは **UTF-8**、1行に1件。
- 月は英語の略称（`Nov` など）。タイムゾーンは `+0900`（日本時間）の形式。
- サイズは整数、または送信データがないことを表す `-`。

`log_parser.load_log()` は、1行を次の辞書に変換し、そのリストを返します。

```python
{"ip": "192.0.2.10", "timestamp": datetime(2026, 11, 15, 10, 0, 5, tzinfo=+09:00),
 "method": "GET", "path": "/index.html", "status": 200, "size": 2048}
```

**形式に合わない行**（ステータスコードがない、IP アドレスや日付が不正 など）は、正常なデータとして扱わず、**行番号と内容を別のリストに記録**します。黙って捨てたり、正常なデータに混ぜたりしません。空行は無視します。

### サンプルログ（`data/sample_access.log`）

**架空のデータ**です。IP アドレスには、ドキュメント用に予約されたアドレス範囲（`192.0.2.0/24`、`198.51.100.0/24`、`203.0.113.0/24`）だけを使っています。実在の利用者の情報は含まれていません。

全48行（2026年11月15日 10:00〜10:30）で、次のパターンを含みます。

| パターン | IP アドレス | アクセス回数 | 404 回数 | 内容 | 想定される検出結果（閾値 10 / 5） |
| --- | --- | ---: | ---: | --- | --- |
| A：通常アクセス | 192.0.2.10 | 5 | 0 | 30分間に数回、主に 200 | 検出されない |
| A：通常アクセス | 192.0.2.20 | 5 | 1 | 古いキャンペーンページで 404 が1回 | 検出されない |
| A：通常アクセス | 198.51.100.7 | 4 | 0 | | 検出されない |
| A：通常アクセス | 198.51.100.23 | 6 | 1 | 画像の 404 が1回 | 検出されない |
| A：通常アクセス | 203.0.113.5 | 3 | 0 | | 検出されない |
| **B：アクセス集中** | **203.0.113.50** | **15** | 0 | 10:12:00〜10:12:28 の約30秒に15回（すべて 200） | **アクセス集中を検出** |
| **C：404 エラー集中** | **198.51.100.66** | **9** | **8** | 10:20 台の約30秒に、存在しない8種類の URL へアクセス | **404エラー集中を検出** |
| 不正な行 | （29行目） | — | — | ステータスコードが `-` になっている | 読み込まず、不正な行として報告 |

正しく読み込めるのは **47件**、異なる IP アドレスは **7個**です。

## 5. 線形探索による集計（`detection.count_linear`）

IP アドレスを入れた**リスト**と、回数を入れたリストを用意し、ログ1件ごとに IP アドレスをリストの先頭から順に探します（教科書の `seq_search()` を使用）。

```python
ips = []            # これまでに見つかった IP アドレス
access_counts = []  # 同じ位置の IP のアクセス回数

for record in records:
    index = seq_search(ips, record["ip"])   # 見つからなければ -1
    if index == -1:                         # 初めての IP：末尾に追加
        ips.append(record["ip"])
        access_counts.append(0)
        index = len(ips) - 1
    access_counts[index] += 1
```

404 エラー回数も、同じ位置に対応する `error_404_counts` リストで数えます。
IP アドレスが増えるほど、1回の探索で調べる要素が増えていきます。

## 6. 辞書による集計（`detection.count_dict`）

Python の**辞書（dict）**は、キー（IP アドレス）から値（回数）をすぐに取り出せるデータ構造です（内部はハッシュ表）。

```python
counts = {}
for record in records:
    ip = record["ip"]
    counts[ip] = counts.get(ip, 0) + 1    # まだなければ 0 から数え始める
```

404 エラーも同じように数えます。404 がなかった IP も、0 として辞書に含めます。

**2つの方法は同じ結果になります**（IP の並び順は違ってよい）。`starter.py` では、線形探索版のリストを `dict(zip(ips, access_counts))` で辞書にして比べ、`MATCH` と表示します。

## 7. 理論計算量の比較

ログ件数を **N**、異なる IP アドレス数を **U** とします。

| | 時間計算量 | 集計用データのメモリ |
| --- | --- | --- |
| 線形探索による集計 | **O(N × U)**（典型的な上界） | O(U) |
| 辞書による集計 | **平均 O(N)**（検索・更新が平均 O(1) と仮定） | O(U) |

- **線形探索**：ログ1件ごとに、最大 U 個の IP を順に調べるため O(N × U)。U が N に比例して増える場合（ほとんどが異なる IP など）は、**O(N²)** になり得ます。
- **辞書**：検索・更新が平均的に O(1) なので、N 件の集計は平均 O(N)。ただし、**ハッシュ衝突**が多いと最悪時の性能は悪くなります。
- **メモリ**：どちらも IP ごとの集計結果を保持するので概ね O(U)。ただし、Python のリストと辞書では、同じ U でも**実際のメモリ使用量が異なる**場合があります（`tracemalloc` で測ってみましょう）。
- Big-O は漸近的な評価であり、実測時間そのものではありません。

## 8. 異常検出と攻撃判定の違い

`starter.py` の先頭で、閾値を設定しています。

```python
ACCESS_THRESHOLD = 10       # アクセス回数がこの値以上なら「アクセス集中」
ERROR_404_THRESHOLD = 5     # 404エラー回数がこの値以上なら「404エラー集中」
```

> ⚠️ これらの閾値は**教育用の仮設定**であり、実際の攻撃検出の基準ではありません。適切な値は、サイトの規模・利用者数・時間帯などによって大きく変わります。

この教材が行うのは「**異常検出**」（いつもと違う、調査が必要な IP を見つけること）であり、「**攻撃判定**」（攻撃であると確定すること）ではありません。

- 検出結果の表現：「アクセス集中を検出」「404エラー集中を検出」「調査が必要なIP」
- 使わない表現：「攻撃者を特定した」「攻撃を確定した」

実際の運用では、検出された IP について、アクセス内容、時間帯、他のログ、利用者への確認などを組み合わせて、人が判断します。
また、**誤検知**（正常なアクセスを異常と判定）と**見逃し**（異常を検出できない）の両方が起こり得ます（Advanced C）。

## 13. Advanced Research：発展課題

必須課題を終えたチームが挑戦する課題です。**Advanced A〜D のうち、チームの能力と時間に応じて1つ以上を選択**してください。すべてを実装する必要はありません。
どのテーマでも、**架空のログ（サンプルログ、または自分たちで生成した合成ログ）だけ**を使ってください。

### Advanced A：時間窓によるアクセス集中の検出

**目的**：総アクセス回数ではなく、**短時間のアクセス急増**を検出する。

1. 1分間・5分間などの時間窓を設定する。
2. IP 別の時間窓内アクセス数を集計する（`record["timestamp"]` を使う）。
3. 総アクセス回数による判定と比較する。
4. 突発的なアクセス集中を検出する。
5. 時間窓の長さによる検出結果の違いを考察する。

発展的には、**スライディングウィンドウ**（窓を少しずつずらしながら数える）を実装してください。キュー（`collections.deque`）に時間窓内のアクセスを入れ、古いものを取り出していく方法があります。

> 例えば、30分間に少しずつ15回アクセスする利用者と、30秒間に15回アクセスする 203.0.113.50 は、総回数では区別できません。

### Advanced B：404 エラーのパターン分析

**目的**：404 の回数だけでなく、アクセスした URL のパターンを分析する。

1. IP 別 **404 エラー率**（404 回数 ÷ アクセス回数）を計算する。
2. IP 別に、**異なる URL への 404 アクセス数**を集計する。
3. **同じ URL への繰り返しアクセス**（リンク切れの可能性）と、**多数の異なる URL へのアクセス**（探索行動の可能性）を区別する。
4. 404 エラー率とアクセス回数を組み合わせて異常候補を検出する。
5. 正常なリンク切れと不審な探索行動の違いを考察する。

> ⚠️ 実在する Web サイトへのスキャンは行わず、**架空のログのみ**を使用してください。

### Advanced C：動的閾値と誤検知の評価

**目的**：固定閾値の問題点を分析し、より柔軟な異常検出を研究する。

1. 正常ログのアクセス回数の分布を調べる。
2. 平均値・標準偏差を計算する（`statistics` モジュール）。
3. 中央値や分位点（例：上位 1%）を使った閾値を検討する。
4. 固定閾値と動的閾値の検出結果を比較する。
5. 正常アクセスを異常と判定する**誤検知**を調べる。
6. 異常アクセスを**見逃す**ケースを調べる。

発展的には、合成データに「正常／異常」の**正解ラベル**を付けて、**Precision（適合率）・Recall（再現率）・F1-score** を計算してください。

> 合成データのラベルは**生成時の設定に基づくもの**であり、実世界の攻撃判定の正解を保証するものではありません。

### Advanced D：大量ログの高速処理

**目的**：ログ件数が増えたときに、どのアルゴリズムやデータ構造が有利かを調べる。

1. N = 1,000 / 10,000 / 100,000 などの合成ログを生成する（`benchmark.make_records()`）。
2. 線形探索版と辞書版の処理時間を比較する。
3. 異なる IP アドレス数 U を変更する。
4. メモリ使用量を比較する。
5. ファイルを一度に読み込む方法と、1行ずつ処理する方法を比較する（合成ログをファイルに書き出して試す）。
6. **ソート＋二分探索**を用いた集計方法を発展的に検討する。

> ソート＋二分探索では、**ソートや、リストへの挿入・更新のコストも含めて**評価してください。整列済みの IP リストに新しい IP を挿入すると、後ろの要素をずらすために O(U) かかることがあります。
> 「検索が O(log U) だから、集計全体が O(N log U) になる」と**断定しない**でください。

## 14. 実験条件と評価指標

### 記録すべき実験条件

- PC 環境（CPU、メモリ）、OS、Python のバージョン
- ログ件数 N、異なる IP 数 U、404 の割合、乱数シード
- 閾値（固定・動的）、時間窓の長さ
- 測定回数と、平均値・中央値などの集計方法

### 評価指標

| 指標 | 内容 |
| --- | --- |
| 処理時間 | 集計処理だけを `time.perf_counter()` で測る（ログ生成・ファイル読み込み・表示の時間は含めない） |
| メモリ使用量 | `tracemalloc` などで測る |
| 集計結果の一致 | 線形探索版と辞書版で同じ結果か |
| 検出結果 | 検出された IP、誤検知・見逃しの数 |
| Precision / Recall / F1 | 正解ラベル付きの合成データを使う場合（Advanced C） |

### 注意

- 線形探索版は N と U が大きいと非常に遅くなります。**最初は小さい値から**試してください。
- 同じデータ（同じ乱数シード）で両方の方法を測ってください。
- 測定は複数回行い、平均値・中央値を比べてください。

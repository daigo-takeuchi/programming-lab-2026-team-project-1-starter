# TASKS：C-1 チーム開発課題

`【教員記入】` の部分は、担当教員が授業の前に記入します。

## 1. 演習の目的

サイバーセキュリティを題材に、データを読み、数え、比べ、異常の候補を見つけるプログラムを作ります。
基本のプログラムを完成させた後、それを改良し、さらに**チームで考えた独自の機能**を作って発表します。

## 2. テーマの選択

チームで次の 5 つから **1 つ**を選びます（選び方：【教員記入】）。

| テーマ | 章 | 内容 |
| --- | --- | --- |
| C-1A | 第4章 | 通信の回数と宛先ポートの種類から、ポートスキャンや通信の集中を見つける |
| C-1B | 第5章 | ログインの失敗回数から、不正ログインの試みを見つける |
| C-1C | 第6章 | URL の文字列から、不審な Web リクエストを見つける |
| C-1D | 第7章 | ファイル一覧を比べて、追加・削除・書き換えを見つける |
| C-1E | 第8章 | 送信データの量から、異常に大量のデータ送信を見つける |

## 3. 課題の進め方（4 つの段階）

**TODO をすべて埋めたら終わり、ではありません。** 次の順に進めます。

### 段階 1：基本プログラムの完成（必須）＝ Level 1

担当テーマの課題1〜4 を実装します。Mini Dataset と Tiny Dataset の【動作確認】がすべて `[OK]` になれば完成です。

| テーマ | 課題1 | 課題2 | 課題3 | 課題4 |
| --- | --- | --- | --- | --- |
| C-1A | `filter_by_source` | `count_connections` | `summarize_connections_baseline` | `detect_high_frequency_sources` |
| C-1B | `filter_failed_logins` | `count_failed_logins` | `summarize_failures_baseline` | `detect_suspicious_users` |
| C-1C | `get_url_length` | `detect_long_urls` | `contains_any_pattern` | `detect_suspicious_requests` |
| C-1D | `file_exists` | `find_added_files` | `find_deleted_files` | `compare_file_lists_baseline` |
| C-1E | `filter_transfers_by_source` | `sum_transfer_bytes` | `summarize_transfer_baseline` | `detect_large_transfers` |

課題1・2 は他の課題に依存しないので、同時に分担できます。

### 段階 2：基本プログラムの改良（推奨）＝ Level 2

Level 2 の改良課題に取り組みます。改良には 2 種類あります。

- **効率化**：同じ結果を、より少ない手間で求める（辞書・集合）。基本版と結果が同じことを確かめ、実行時間を比べます。
- **検出方法の改良**：判定のしかたを変える。結果は変わってかまいません。何が見つかるようになったかを比べます。

Level 2 の代わりに、**同じくらいの量のチーム独自の改良**を行ってもかまいません（事前に教員に相談してください）。

### 段階 3：チーム独自の機能開発（必須）

自分たちで問題を決めて、**独自の機能か改良を 1 つ以上**作ります。難しい機能である必要はありません。
大切なのは、**自分たちで考え、設計し、実装し、動作を確かめる**ことです。

| テーマ | 独自の機能の例 |
| --- | --- |
| C-1A | 通信元別のランキング、閾値を変えたときの結果の比較、宛先ポートの種類別の集計、時間帯別の通信回数 |
| C-1B | 認証失敗回数のランキング、ユーザー別と接続元別の比較、複数の閾値による結果の比較 |
| C-1C | 新しい判定ルールの追加、ルール別の検出件数の比較、スコア方式の改良、誤検出の分析 |
| C-1D | ファイルの変化の履歴の表示、ファイルの種類（拡張子）別の集計、3 つ以上の時点の比較 |
| C-1E | 送信量のランキング、通信元ごとの閾値、送信量の時間的な変化 |

Notebook の各章の N.9（Level 3）にある発展案を選んでもかまいません。独自の機能にも、自分たちで考えた動作確認（`check` を使ったテスト）を付けてください。

### 段階 4：評価・考察・発表（必須）

- 完成したプログラムが正しく動くことを確かめる。
- 基本版と改良版を比べる（実行時間、または見つかったものの違い）。
- 独自の機能の意義、結果、限界、今後の改善案を説明する。

## 8. Git の使い方（例）

```bash

# Notebook を編集して保存

git commit -m "C-1B 課題2 count_failed_logins を実装"
```

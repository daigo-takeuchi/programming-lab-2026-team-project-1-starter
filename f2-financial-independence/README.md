## 2. 資産形成とは何か

この教材での**資産形成**は、毎年の所得の一部を貯蓄し、それを運用（投資）して資産を増やしていくことです。

- **年間所得**：1 年間に得る収入（この教材では税・社会保険料を引いた後の額とみなす単純化）
- **貯蓄率**：所得のうち貯蓄に回す割合
- **生活費**：所得のうち貯蓄しなかった分（Core では 生活費 = 所得 × (1 − 貯蓄率)）
- **投資収益率**：資産が 1 年で何 % 増えるか（Core では毎年一定）

資産形成の速さは、**どれだけ貯めるか（貯蓄率・所得）**と、**どれだけ増えるか（収益率・期間）**の両方で決まります。

## 3. 貯蓄率と複利

```text
Annual Savings = Annual Income × Savings Rate
Assets[t+1]    = Assets[t] × (1 + r) + Savings[t]
```

- **複利**：前の年までに増えた分（収益）にも、次の年の収益が付く。期間が長いほど効果が大きい。
- 例（架空）：所得 400 万円・貯蓄率 20%（年 80 万円）・収益率 3% で 22 歳から積み立てると、65 歳時点の資産は約 6,839 万円で、そのうち拠出した貯蓄の合計は 3,440 万円、残りは投資収益です（`experiments.py` の Experiment 2、Notebook 01）。
- 貯蓄率を上げると、**貯蓄が増える**効果と、**生活費が減る（＝ FIRE 目標が下がる）**効果が同時に起こります（6章）。

## 4. 投資収益率

- この教材の収益率（0%〜8%）は**教育用の仮定**です。実際の投資の収益率は毎年大きく変動し、マイナスの年もあります。過去の収益率は将来を保証しません。
- Core では**毎年同じ収益率**を仮定します。収益率の変動（確率モデル）は Advanced A・B で扱います。
- 収益率が負でも計算できます（−1 以上。−1 = 資産がすべて失われる）。
- **投資収益率と取り崩し率は別のものです**（7章）。

## 5. FIRE とは何か

**FIRE**（Financial Independence, Retire Early）は、資産からの取り崩し（と運用益）で生活費をまかなえるだけの資産を早く築き、働かなくても生活できる状態（経済的自立）を目指す考え方です。

この教材では、FIRE を次の 2 つの意味に分けて考えます（RQ5）。

1. **目標到達**：資産が FIRE 目標資産（6章）に到達した年齢
2. **持続**：その時点でリタイアしたとき、資産が一定の年齢（例：100 歳）まで生活費をまかない続けられるか

**1 を満たしても 2 を満たすとは限りません。** サンプルデータでも、目標に到達した年齢でリタイアすると資産が途中で尽きるシナリオがあります（13章の出力）。

## 6. FIRE 目標資産

```text
FIRE Target = Annual Expenses / Withdrawal Rate
```

- 例：年間生活費 300 万円、取り崩し率 4% → 300 / 0.04 = **7,500 万円**（生活費の 25 倍）
- 取り崩し率が 0 だと目標が無限大になるので、0 は受け付けません（`fire_target` は `ValueError`）。
- 生活費が下がると、**目標が下がる**ので FIRE は早まります。

## 7. 4% ルールとその限界

「資産の 4% を毎年取り崩しても、資産はおおむね長く持つ」という経験則（4% ルール）があります。この教材では **4% を教育用の初期仮定**として使いますが、次の点に注意してください。

- **4% ルールは保証ではありません。** 特定の国・時代の過去のデータにもとづく経験則で、すべての国・時代・投資条件・退職期間で安全とは限りません。
- **投資収益率と取り崩し率は異なります。** 取り崩し率は「資産のうち何 % を生活費として使うか」、収益率は「資産が何 % 増えるか」です。収益率が取り崩し率より低い状態が続けば、資産は減っていきます（Notebook 03：目標ちょうどの資産でリタイアし、収益率 3% なら資産はいずれ尽きる）。
- **退職期間が長いほど不確実性は大きくなります。** 早期リタイアでは取り崩しの期間が 40〜50 年以上になることがあります。
- **Core では税金・インフレ・手数料・年金の影響を省略しています**（Advanced D）。インフレがあれば生活費は年々増え、税・手数料があれば手元に残る額は減ります。

## 8. 年齢別資産シミュレーション

`financial_model.py`

| 用語 | この教材での定義 |
| --- | --- |
| a 歳の年 | a 歳の誕生日から a+1 歳の誕生日までの 1 年間 |
| 年初資産 `start_assets` | a 歳の年の始めの資産 ＝ **「a 歳時点の資産」** |
| 投資収益 `investment_return` | 年初資産 × 収益率（年初の資産にだけ収益が付く） |
| 年間貯蓄額 `savings` | 年**末**に拠出する（その年の収益は付かない） |
| 年末資産 `end_assets` | 年初資産 × (1 + r) + 貯蓄額 ＝ 次の年の年初資産 |
| 計算期間 | **開始年齢の年から、終了年齢の前の年まで**（22 歳〜79 歳の年、T = 58 年）。終了年齢（80 歳）時点の資産は、最後の年の年末資産 |

各年について、年齢・年初資産・年間所得・年間貯蓄額・投資収益・年末資産を記録します（`simulate_accumulation`）。`assets_by_age` は「年齢 → その年齢時点の資産」の 2 つのリスト（開始年齢〜終了年齢の T + 1 個）を返します。

**入力の検証**：年齢は整数（`True`/`False` は不可）、開始年齢 < 終了年齢、初期資産・所得 ≥ 0、貯蓄率 0〜1、収益率 ≥ −1。違反すると `TypeError` / `ValueError` です。

## 9. リタイア後の取り崩し

`retirement_model.py`

```text
Assets[t+1] = Assets[t] × (1 + r) − Annual Expenses
```

- 年初の資産に収益率を適用し、年**末**に生活費を取り崩します。
- **0 で打ち切る方式**：資産が足りない年は、あるだけを取り崩して資産は 0 になります（負にはしない）。足りなかった額は `shortfall` に記録します。資産が 0 になった後の年も、記録は続けます（収益 0・取り崩し 0）。
- **資産枯渇年齢**（`depletion_age`）：年末資産が 0 以下になった最初の年の年齢。最後まで残れば `None`。
- **全額まかなえた年数**（`years_sustained`）、**最後まで持続したか**（`is_sustainable`）も計算します。
- 生活費が 0 なら、資産 0 でも「枯渇」とはみなしません。

## 10. FIRE 達成年齢の探索

`fire_analysis.py`

### 線形探索（Core）

年齢別資産を**若い順に**調べ、初めて FIRE 目標以上になった年齢を答えにします。

1. 各年齢で「目標以上か」を表す真偽値のリストを作る（O(T)）
2. 教科書の `seq_search`（線形探索）で、最初の `True` の位置を探す（O(T)）
3. 見つからなければ `None`（未達成）。初期資産がすでに目標以上なら開始年齢

線形探索は、**資産がどのように変化しても**（減る年があっても）正しく動きます。

### 二分探索を使える条件と限界

`fire_age_binary` は二分探索で同じ答えを求めます（O(log T)）。ただし：

- **前提**：資産が年齢とともに**減らない（単調非減少）**こと。収益率 ≥ 0 かつ貯蓄 ≥ 0 なら必ず満たされます。
- 収益率が負の年がある（Advanced A・B）、途中で取り崩す、などの場合は単調でなくなり、二分探索は**誤った答え**を返し得ます。そのため `fire_age_binary` は既定で前提を確認し、満たさなければ `ValueError` にします。
- 前提の確認自体に O(T) かかるので、確認するなら線形探索と同じオーダーです。そもそもシミュレーション自体が O(T) なので、**この問題では二分探索で全体が速くなるわけではありません**。二分探索が役立つのは、例えば「FIRE 達成年齢が x 歳以下になる最小の貯蓄率」を探すように、**1 回の評価が重い**場合です（そのときも、貯蓄率に対して結果が単調であることを確かめる必要があります。`optimization.py` の TODO 3）。
- 教科書の `bin_search`（第3章）は「キーと**等しい**要素」を探す関数で、「条件を満たす**最初の**位置」は返しません。そのため、境界を探す形に書き直しています。

### RQ5：目標到達 ≠ 持続

FIRE 達成年齢は「目標に到達した年齢」で、その後の持続は保証しません。`optimization.evaluate_scenario` は、FIRE 達成年齢でリタイアした場合の取り崩しも計算します。

## 11. アルゴリズムと計算量

T = シミュレーションの年数、N = シナリオ数、K = 候補条件の数、M = モンテカルロの試行回数とします。

| 処理 | 計算量 | この教材 |
| --- | --- | --- |
| 資産形成シミュレーション | **O(T)** | `simulate_accumulation`（1 年ずつ更新） |
| FIRE 達成年齢の探索 | **O(T)**（線形探索） | `fire_age`。二分探索は O(log T) だが単調性が前提（10章） |
| リタイア後の取り崩し | **O(T)** | `simulate_withdrawal` |
| 複数シナリオの比較 | **O(NT)** | `evaluate_scenario` × N |
| パラメータの全探索 | **O(KT)** | `sweep_savings_rate`・`sweep_return`・`sweep_expenses` |
| 2 つのパラメータの組合せ | **O(K₁K₂T)** | `grid_fire_age`（ヒートマップ） |
| 最適条件の選択 | **O(K)** | `best`（教科書 `max_of` + `seq_search`） |
| 順位付け | 比較ソートでは O(N log N) が代表的 | 教科書の単純挿入ソート（O(N²)、N が小さいので十分） |
| モンテカルロシミュレーション | **O(MT)** | Advanced A（未実装） |

> **理論計算量と実測時間は別のものです。** 計算量は「問題が大きくなったときの増え方」で、実際の時間は実装・Python の速さ・コンピュータで決まります。この教材の規模（T = 58、K = 5〜30）では、どの計算も一瞬で終わります。モンテカルロ法で M = 10,000 回、さらに条件の全探索を組み合わせると、計算量（M × K × T）が効いてきます。

### 「最適」の定義（`optimization.py`）

| 目的 | 方向 |
| --- | --- |
| FIRE 達成年齢 | 最小化（`best(rows, "fire_age", minimize=True)`） |
| 一定年齢（65 歳）での資産 | 最大化（`assets_at_report`） |
| 現役時の生活費 | 最大化（`current_expenses`） |
| リタイア後の資産持続年数 | 最大化（`years_sustained`） |

- 貯蓄率を上げれば FIRE は早まり得ますが、**今の生活費は減ります**。FIRE 達成年齢だけを最小化すると「候補の中で最も高い貯蓄率」が選ばれるだけで、貯蓄率 100%（生活費 0）は現実の答えではありません。最低生活費などの**制約**や、複数の指標のトレードオフをどう扱うかは研究の中で決めます（Advanced C）。
- **未達成（`None`）の候補は除いて**選びます。すべて未達成・候補が空なら `None`。
- **同順位の規則**：同じ値が複数あるときは、**候補リストで最初に現れる条件**を選びます（順位付けでも元の順番を保つ）。

### 教科書との対応

1. **配列による年齢別資産の管理**：年齢別の資産をリストに入れ、添字 = 年齢 − 開始年齢で管理します（第2章 配列）。`assets_by_age` は年齢と資産の 2 つのリストを返します。
2. **ループによる複利計算**：for ループで 1 年ずつ「年初資産 × (1 + r) + 貯蓄」を計算します。前の年の結果を使う**逐次的な**計算です。
3. **線形探索による FIRE 達成年齢の検出**：「目標以上か」の真偽値のリストを作り、教科書の `seq_search`（第3章）で最初の `True` を探します。O(T)。
4. **最大値・最小値探索による条件比較**：候補ごとの評価値をリストにし、教科書の `max_of`（第2章）で最大値、`seq_search` でその位置を求めます。最小化は値の符号を反転して最大値を求めます。
5. **ソートによるシナリオ順位付け**：(未達成か, 評価値, 元の番号) の組を教科書の単純挿入ソート（第6章、安定）で並べます。未達成は最後、同順位は元の順番です。
6. **全探索による貯蓄率・収益率の比較**：候補をすべて試して比べます。O(KT)、2 つの組合せなら O(K₁K₂T)。
7. **二分探索を利用できる条件と限界**：資産が単調非減少のときだけ使えます。教科書の `bin_search` は等しい値を探す関数なので、境界の探索には書き直しが必要です（10章）。

## 17. Advanced Research

Core Research を終えたチームが取り組む課題です。**Advanced A〜E のうち 1 つ以上を選択**してください。すべてを実装する必要はありません。

### Advanced A：モンテカルロシミュレーション

- 年間収益率を確率変数にする（例：毎年 `rng.gauss(平均, 標準偏差)`）。
- 複数回（M 回）シミュレーションし、FIRE 達成年齢の**分布**を求める（未達成の割合も）。
- 平均値と中央値を比較する（分布が偏っていると違いが出る）。
- **乱数シードを固定**する（`random.Random(seed)`）。シードと試行回数を報告に書く。
- 計算量は O(MT)。収益率が負の年があると資産は単調でなくなるので、FIRE 達成年齢は線形探索で求める。

### Advanced B：Sequence of Returns Risk（収益率の順序のリスク）

- **同じ平均収益率**でも、収益率が起こる**順序**を入れ替えて、リタイア後の資産推移を比べる。
- 取り崩しの初期に下落が来る場合と、後に来る場合の影響を調べる。
- 多数の順序（ランダムな並べ替え）で、資産枯渇の確率を分析する。

### Advanced C：貯蓄率の最適化

- FIRE 達成年齢を最小化する。
- 現在の生活費（最低生活費）を**制約条件**にする（例：年 250 万円を下回らない）。
- 制約付き最適化として、全探索・二分探索（単調性を確かめた上で）などを比べる。
- 「早く FIRE する」と「今の生活の質」のトレードオフを、複数の指標で示す。

### Advanced D：インフレ・税金・年金

- インフレ率を導入し、**名目資産と実質資産**（物価で割り引いた価値）を区別する。
- 税金（運用益・所得）、社会保険料を考慮する。
- 公的年金（一定年齢から毎年の収入）を考慮する。

> 制度や税率は変更されます。現実の制度を使う場合は、**最新の公的情報**（国税庁、日本年金機構、厚生労働省など）を確認し、参照日を記録してください。

### Advanced E：F1 との統合

F1「キャリア選択と生涯所得の最適化」の所得モデルと連携します。

- 年齢別所得（F1 の `scenarios.incomes` の出力のような、年齢ごとの年収のリスト）を、F2 の資産形成の所得として使う。
- 転職・資格取得・進学費用が、貯蓄・FIRE 達成年齢にどう影響するかを調べる。
- **F1 のコードを直接変更せず**、データ形式の互換性（単位：万円、年齢の範囲、リストの添字と年齢の対応）を検討する。例えば、F1 の結果を JSON や CSV に書き出し、F2 で読み込む。
- **F1 リポジトリへの依存は Core Research では必須にしません。**

## 19. モデルの限界と倫理的配慮

- **本教材は教育用シミュレーションです。** 架空の所得・生活費・収益率を使っています。
- **将来の投資収益を予測・保証するものではありません。** 実際の収益率は毎年変動し、損失が出る年もあります。
- **FIRE 目標への到達は、リタイア後の生活の持続可能性を保証しません**（RQ5）。
- **4% ルールは普遍的な安全基準ではありません**（7章）。
- **税金・手数料・インフレ・年金・社会保険料・医療費・介護費・突発的な支出などを Core では省略しています。**
- **個人の投資判断を推奨するものではありません。実際の金融商品を推奨しません。** 実際の資産形成・投資は、公的な情報や専門家の助言を参考に、自分の状況に合わせて判断してください。
- **所得や資産だけで人生の幸福を評価しないでください。** 仕事のやりがい、健康、家族や友人との時間、社会とのつながりなど、資産では測れないものがあります。
- 「高所得」「高貯蓄」などのシナリオは計算の条件であり、特定の生き方を良い・悪いと評価するものではありません。

### 4. コピーと確認のコマンド例

```bash
cd f2-financial-independence
SRC="<展開したフォルダ>"        # 各自の環境に合わせる

cp -i "$SRC/chap06/insertion_sort.py" textbook/insertion_sort.py
cp -i "$SRC/chap02/max.py" textbook/max.py
cp -i "$SRC/chap03/ssearch_while.py" textbook/ssearch_while.py

# 原本とコピーの SHA-256 が一致することを確認する
sha256sum "$SRC/chap06/insertion_sort.py" textbook/insertion_sort.py
sha256sum "$SRC/chap02/max.py" textbook/max.py
sha256sum "$SRC/chap03/ssearch_while.py" textbook/ssearch_while.py

python3 starter.py                          # 実行確認
python3 -m unittest discover -s tests -v    # テスト
```

配置した教科書のコードは、リポジトリ直下の `.gitignore` によって Git の追跡対象から除外されます（`git status` に表示されなければ正常です）。
`git add -f` などで教科書のコードを commit・push しないでください。

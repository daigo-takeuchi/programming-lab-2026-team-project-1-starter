## 1. 研究テーマ

**A2：基本的なソートアルゴリズムの性能比較**

同じデータを、バブルソート・選択ソート・挿入ソートの3つの方法で並べ替えて比べます。
データ数 N や初期データの並び順を変えたときの処理時間、比較回数・交換回数などを実験で調べ、計算量の観点から考察します。

## 2. 研究の背景

### ソートアルゴリズムとは

ソート（整列）とは、データを決まった順序（昇順・降順など）に並べ替える処理です。
成績順の並べ替え、ネットショップの「価格の安い順」表示、二分探索の前処理など、さまざまな場面で使われます。
同じ結果になる並べ替えでも、その**手順（アルゴリズム）**によって、かかる時間が大きく変わります。

### バブルソート（単純交換ソート）

**隣り合う2つの要素を比べ、順序が逆なら交換する**ことを繰り返します。
教科書の `bubble_sort1.py` は、リストの**末尾から先頭に向かって**比較・交換を行い、1回の走査（パス）ごとに、残りの中で最も小さい値が先頭側に確定します。

```text
[8, 3, 5, 1]  末尾から比較
  5 > 1 → 交換 [8, 3, 1, 5]
  3 > 1 → 交換 [8, 1, 3, 5]
  8 > 1 → 交換 [1, 8, 3, 5]   ← 1パス目終了：最小値 1 が先頭に確定
```

### 選択ソート（単純選択ソート）

**未ソート部分から最小値を探し、未ソート部分の先頭と交換する**ことを繰り返します。

```text
[8, 3, 5, 1]  最小値 1 を探して先頭の 8 と交換 → [1, 3, 5, 8]
[1 | 3, 5, 8] 最小値 3 を探して先頭の 3 と交換 → [1, 3, 5, 8]（同じ位置でも交換する）
...
```

### 挿入ソート（単純挿入ソート）

**整列済みの部分に、次の要素を正しい位置へ挿入する**ことを繰り返します。トランプの手札を並べる方法に似ています。
挿入する値（`tmp`）より大きい要素を1つずつ右へずらし（移動）、空いた位置に `tmp` を入れます。

```text
[3, 8 | 5, 1]  5 を挿入：8 を右へずらし、3 の後ろへ → [3, 5, 8 | 1]
[3, 5, 8 | 1]  1 を挿入：8, 5, 3 を右へずらし、先頭へ → [1, 3, 5, 8]
```

### 3つのアルゴリズムの比較

| | バブルソート | 選択ソート | 挿入ソート |
| --- | --- | --- | --- |
| 基本の操作 | 隣どうしを比較・交換 | 最小値を探して交換 | ずらして挿入 |
| 比較回数（教科書の実装） | 常に n(n−1)/2 | 常に n(n−1)/2 | 最良 n−1 〜 最悪 n(n−1)/2 |
| 交換・移動の回数 | 交換 0 〜 n(n−1)/2 回 | 交換は常に n−1 回 | 移動 0 〜 n(n−1)/2 回 |
| 並び順の影響 | 比較回数は受けない（交換回数は受ける） | ほとんど受けない | 大きく受ける |
| 安定性（同じ値の順序を保つか） | 安定 | 安定ではない | 安定 |

### データ数 N と計算量

3つとも、基本的に「すべての要素の組を比べる」ような二重ループの構造です。
そのため、データ数 N が2倍になると処理時間はおよそ **4倍（2²倍）**、10倍になるとおよそ **100倍** になります。これを **O(n²)** と表します。

### 初期データの並び順によって処理時間が変わる理由

アルゴリズムによって「どこで処理を省略できるか」が違うためです。

- **挿入ソート**は、すでに整列済みに近いデータだと、ずらす必要がほとんどなく、すぐに次の要素へ進めます。逆に降順のデータでは、毎回すべてを右へずらすことになります。
- **バブルソート**（今回の実装）は、比較回数は並び順に関係なく一定ですが、交換回数は並び順で変わります（昇順なら0回、降順なら最大）。
- **選択ソート**は、最小値を探すために毎回未ソート部分をすべて調べるので、並び順の影響をほとんど受けません。

## 3. 理論計算量

教科書の実際の実装に即した時間計算量は次のとおりです。

| アルゴリズム | 最良時間計算量 | 平均時間計算量 | 最悪時間計算量 |
| --- | --- | --- | --- |
| バブルソート（今回の `bubble_sort1.py`） | O(n²) | O(n²) | O(n²) |
| 選択ソート（`selection_sort.py`） | O(n²) | O(n²) | O(n²) |
| 挿入ソート（`insertion_sort.py`） | O(n) | O(n²) | O(n²) |

- 今回の `bubble_sort1.py` は、**交換が発生しなかった場合に途中で終了する処理（早期終了）を備えていない**ため、昇順データでも O(n²) です。
  （教科書には、早期終了などの改良版も掲載されています。発展課題として調べてみましょう。）
- 選択ソートも、入力順序によらず、基本的な比較回数は O(n²) です。
- 挿入ソートは、すでに昇順に並んでいる場合には O(n) になります。
- 3つのアルゴリズムの平均的な時間計算量は、通常 O(n²) です。
- これらは時間計算量の**漸近的な評価**（N が大きくなったときの増え方）であり、**実測時間そのものではありません。**

## 7. 比較実験の注意点

- **3つのアルゴリズムに同じ初期データを使用する。**
- **各ソート関数はリストを直接変更するため、毎回 `data.copy()` でコピーを作成する。** コピーせずに続けて実行すると、2番目以降のアルゴリズムは「すでにソート済みのデータ」を受け取ることになり、公平な比較になりません。
- **データ生成・コピー・結果表示の時間は、原則としてソート処理時間に含めない。**
- **短時間の測定では誤差が大きいため、複数回測定する。** 平均値や中央値を使いましょう。
- **乱数を使用する場合は、乱数シードを記録する。**（例：`random.seed(2026)`）同じデータで再実験できるようにするためです。
- **最初は小さい N から試す。** O(n²) のアルゴリズムでは、N を大きくすると処理時間が急増します（N を10倍にすると約100倍）。
- **計算量が同じ O(n²) でも、実際の実行時間が同じとは限らない。** 1回の比較・交換・移動にかかる手間が違うためです。
- **比較回数・交換回数・要素移動回数は同じ指標ではない。** 何を1回と数えたのか、計測方法を明示してください（例：挿入ソートの「ずらす」操作は交換ではなく移動）。
- **Python 標準の `sorted()` は C 言語で実装された Timsort を利用している。** 教科書の Python 実装と比べるときは、アルゴリズムの違いだけでなく実装言語の違いも影響することに注意してください。

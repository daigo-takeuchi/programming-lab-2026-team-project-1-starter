## 1. 研究テーマ

**A1：線形探索と二分探索の性能比較**

同じ「探索」という処理を、異なる2つのアルゴリズムで行い比べます。
探索結果の正しさ、比較回数、データ数 N と処理時間の関係を実験で調べ、計算量 O(n) と O(log n) の観点から考察します。

## 2. 研究の背景

### 探索アルゴリズムとは

探索（search）とは、たくさんのデータの中から**目的の値（キー）がどこにあるか**を見つける処理です。
探索アルゴリズムは、身近なところで次のように使われています。

- ネットショップの商品検索、図書館の蔵書検索
- データベースで条件に合うレコードを探す処理（インデックスによる高速化）
- 辞書・電話帳・住所録からの検索
- 他のアルゴリズムの部品（重複チェック、挿入位置の決定など）

### 線形探索（Linear Search）

先頭から順に1つずつ、キーと等しいかを調べていく方法です。

```text
data = [2, 5, 8, 12, 17, 21, 30]   key = 17

 2 → 5 → 8 → 12 → 17  見つかった！（インデックス4、比較5回）
```

- データが**整列されていなくても**使えます。
- 運が悪いと（末尾にある・存在しない）、全要素を調べることになります。

### 二分探索（Binary Search）

**昇順に整列済み**のデータに対して、探索範囲の中央の値とキーを比べ、範囲を半分ずつ絞り込む方法です。
教科書のコードでは、範囲の先頭を `pl`、末尾を `pr`、中央を `pc` で表します。

```text
data = [2, 5, 8, 12, 17, 21, 30]   key = 17
index:  0  1  2   3   4   5   6

1回目：pl=0, pr=6, pc=3 → data[3]=12 < 17 なので後半へ（pl=4）
2回目：pl=4, pr=6, pc=5 → data[5]=21 > 17 なので前半へ（pr=4）
3回目：pl=4, pr=4, pc=4 → data[4]=17 見つかった！（インデックス4、比較3回）
```

### 二分探索が整列済みデータを必要とする理由

二分探索は「中央の値がキーより小さければ、**キーは中央より右にしかない**」と判断して左半分を捨てます。
この判断は、データが昇順に並んでいるときだけ正しくなります。
整列されていないデータに使うと、本当は存在する値を「見つからない（-1）」と判定してしまうことがあります。

未整列のデータに二分探索を使いたい場合は、先にソート（並べ替え）が必要です。
ソートにも時間がかかるため、「ソート＋二分探索」の合計時間で考える必要があります。

### O(n) と O(log n) の違い

データ数を N としたとき、最悪の場合の比較回数はおおよそ次のようになります。

| データ数 N | 線形探索 O(n) | 二分探索 O(log n) |
| ---: | ---: | ---: |
| 100 | 100回 | 7回 |
| 1,000 | 1,000回 | 10回 |
| 1,000,000 | 1,000,000回 | 20回 |

- **O(n)**：データ数が10倍になると、時間もおよそ10倍になる。
- **O(log n)**：データ数が2倍になっても、比較回数は1回増えるだけ。

ただし Big-O は「N が大きくなったときの増え方（漸近的な計算量）」を表すもので、実際の秒数そのものではありません。
N が小さいときは、差がほとんど見えないこともあります。

## 6. 比較実験の注意点

- **両アルゴリズムには同じデータと同じ探索対象を与える。**
- **基本比較では昇順の整列済みデータを使用する。**
- **データ生成・ソート・結果表示の時間を、探索処理の時間と区別する。** 測定したい部分だけを `time.perf_counter()` で挟みましょう。
- **実行時間が短すぎる場合は、多数回繰り返して測定する。** 1回の探索は非常に短く、正確に測れないことがあります。
- **繰り返し測定では、測定回数や実行環境（PC、Pythonのバージョン）を記録する。**
- **探索対象の位置によって処理時間が変わる可能性を考慮する。** 線形探索では、先頭の要素はすぐ見つかり、末尾や存在しない値は時間がかかります。
- **重複要素がある場合、線形探索と二分探索が異なるインデックスを返す可能性がある。** 例：`[1, 2, 2, 2, 3]` で 2 を探すと、線形探索は 1、二分探索は 2 を返します。どちらも「探索成功」です。
- **実測時間だけでなく、比較回数や探索範囲の変化も分析すると理解が深まる。**
- **Big-O は漸近的な計算量を表すものであり、実測時間そのものではない。**

### 発展課題（任意）

- **未整列データ**：「線形探索」と「ソート＋二分探索」の総処理時間を比べる。何回以上検索するなら、事前にソートするほうが有利になるか？

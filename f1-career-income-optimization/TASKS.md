# TASKS：F-1 チーム開発課題

`【教員記入】` の部分は、担当教員が授業の前に記入します。

## 1. 演習の目的

キャリア・家族・住宅・世代間の資金移転という身近な問題を題材に、データを読み、1 年ずつ計算し、
条件を満たす選択肢を探して比べるプログラムを作ります。基本のプログラムを完成させた後、それを改良し、
さらに**チームで考えた独自の機能**を作って、性能と結果を評価し、発表します。

この教材は仮定にもとづくプログラミング演習です。結果を「正しい人生設計」や「おすすめの選択」として示さないでください。

## 2. テーマの選択

チームで次の 4 つから **1 つ**を選びます（選び方：【教員記入】）。

| テーマ | 章 | 内容 |
| --- | --- | --- |
| F-1A キャリア選択・教育投資と生涯所得 | 第4章 | キャリアの候補ごとに生涯所得を計算し、条件で絞り込み、並べ、教育費を回収できる年齢を探す |
| F-1B 家族形成・子育て・介護と資源配分 | 第5章 | 2 人の勤務形態と育児・介護の分担の組合せを全探索し、収支と時間の条件を満たす計画を探す |
| F-1C 住宅取得・居住選択と長期家計設計 | 第6章 | 賃貸と購入の費用を比べ、予算以下の住宅を線形探索と二分探索で探して比べる |
| F-1D 世代間資源継承と次世代の生活設計 | 第7章 | 親から子への資金の移転をシナリオごとにシミュレーションし、親の最低生活資金を守れるものを探す |

## 3. 課題の進め方（4 つの段階）

**TODO をすべて埋めたら終わり、ではありません。** 次の順に進めます。

### 第1段階：Level 1 の基本実装（必須）

担当テーマの課題1〜4 を実装します。Mini Dataset と Tiny Dataset の【動作確認】がすべて `[OK]` になれば完成です。

| テーマ | 課題1 | 課題2 | 課題3 | 課題4 |
| --- | --- | --- | --- | --- |
| F-1A | `calculate_working_years` | `salary_at_age` | `lifetime_income` | `summarize_careers` |
| F-1B | `household_income` | `household_expense` | `annual_balance` | `free_hours` |
| F-1C | `annual_rent` | `cumulative_rent` | `ownership_cost` | `find_candidates` |
| F-1D | `annual_balance_of` | `transfer` | `update_assets` | `simulate_transfer` |

F-1B は、課題1〜4 を for 文で組み合わせる【練習：Level 1】（新しい関数は作らない）も行います。

### 第2段階：Level 2 のアルゴリズム実装・改良（推奨）

| テーマ | 課題5 | 課題6 | 課題7 |
| --- | --- | --- | --- |
| F-1A | `filter_careers`（線形探索） | `rank_careers`（ソート） | `find_payback_age`（累積和 + 線形探索） |
| F-1B | `generate_work_pairs`（全探索） | `find_feasible_plans`（制約による絞り込み） | `rank_plans`（ソート） |
| F-1C | `sort_by_price`（安定なソート） | `count_affordable`（二分探索） | `affordable_ids_binary`（境界 + 取り出し） |
| F-1D | `generate_transfer_scenarios`（全探索） | `count_shortage_years`（数え上げ） | `find_feasible_transfers`（制約による絞り込み） |

その後、第8章の担当テーマの節で、データの規模と実行時間の関係を調べます。
比べ方には 2 種類あります。区別して説明してください。

- **アルゴリズムの速度比較**：同じ答えになる 2 つの方法の時間を比べる（例：線形探索と二分探索）。先に結果が同じことを確かめます。
- **条件・目的関数による結果の比較**：評価のしかたを変えると、選ばれる候補が変わる（例：収支が最大と、自由時間が最大）。

Level 2 の代わりに、**同じくらいの量のチーム独自の改良**を行ってもかまいません（事前に教員に相談してください）。

### 第3段階：チーム独自の機能の開発（必須）

自分たちで問題を決めて、**独自の機能か改良を 1 つ以上**完成させます。難しい機能である必要はありません。
大切なのは、**自分たちで考え、設計し、実装し、動作を確かめる**ことです。

- 各章の N.10 に「チーム独自の機能の候補」（各テーマ 4 案）、N.9 に Level 3 の発展案（各テーマ 5 案）と**公開統計への橋渡し演習**があります。そこから選んでも、自分たちで考えてもかまいません。
- **Level 3 の発展案をすべて実装する必要はありません。**
- 独自の機能には、入力・処理・出力、使ったアルゴリズムと計算量、動作確認（`check` を使ったテスト）、モデルの仮定と限界を書きます。

### 第4段階：動作確認・性能評価・考察・発表（必須）

- 完成したプログラムが正しく動くことを確かめる（動作確認がすべて `[OK]`、独自機能のテスト）。
- 性能評価（第8章）またはシナリオの比較を行い、表・グラフで示す。
- 結果の考察と、モデルの限界（各章の「モデルの妥当性と限界」）を説明する。
  「計算が正しい」ことと「現実の予測として正しい」ことを区別してください。

## 10. Git の使い方（例）

```bash
git switch -c feature/f1b-household-income
# Notebook を編集して保存
git add F1_life_planning_starter.ipynb
git commit -m "F-1B 課題1 household_income を実装"
git push -u origin feature/f1b-household-income
```

Notebook は同時に編集すると、まとめる（マージする）のが難しくなります。**担当する章・セルを決め、こまめにコミット**してください。

## 11. 注意事項

- 自分や家族の実際の所得・資産・健康状態などを入力しないでください。仮想の人物・家族を使います。
- 異なる統計の平均値を、同じ人や同じ家族のデータとして扱わないでください。
- 公開統計にない値（例：取引価格データの家賃・通勤時間）を、実測値のように作り足さないでください。仮定値を使う場合は「仮定」と明記します。
- 赤字や資産不足を 0 に置き換えて隠さないでください。

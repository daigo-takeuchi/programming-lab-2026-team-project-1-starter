# シミュレーションの規則（全テーマ共通）

## 1. 単位

| 量 | 単位 | 名前の付け方 |
| --- | --- | --- |
| 金額 | 万円 | 月額は `monthly_`、年額は `annual_`、総額は `purchase_price`・`education_cost` など |
| 年齢 | 歳（整数） | `age`、`start_age`、`retirement_age` |
| 期間 | 年（整数） | `years`、`duration_years` |
| 時間 | 時間／週 | `weekly_` で始める。1 人 168 時間／週 |
| 割合 | 小数（0.02 = 2%） | `annual_growth` |
| 通勤時間 | 分（片道） | `commute_minutes` |
| 床面積 | ㎡ | `floor_area` |

## 2. 時間の流れ

- シミュレーションの 1 年目は `year = 1`。記録するのは**年の終わり（年末）の状態**。
- 初期状態（`assets`／`initial_assets`）は `year = 0` に相当し、履歴のリストには含めない。年数 0 なら空のリスト。
- 年齢との対応：`year = t` の年の年齢は「初期の年齢 + t − 1」（その年の初めの年齢）。
- F-1A の年齢別の計算は「年齢 a の 1 年間」。`start_age ≤ a < retirement_age` の年だけ所得がある（退職年齢の年は含めない）。

## 3. 1 年の処理の順番

| テーマ | 1 年の処理 |
| --- | --- |
| F-1A | 年収 = `initial_salary × (1 + annual_growth) ** (age − start_age)` |
| F-1B | 収支 = 2 人の年収の合計 − (生活費 + 育児費 + 介護費) |
| F-1C | 賃貸：家賃 × 12 を毎年。購入：最初に購入価格、毎年維持費（ローンは Level 3） |
| F-1D | ① 各人の収支を資産に反映 → ② 親から子へ移転。年末の資産を記録 |

F-1D は加減算だけなので、①②の順番を入れ替えても年末の値は同じ。Level 3 で利息などを入れる場合は順番を明記する。

## 4. 守ること

1. **所得と可処分所得を区別する**：年収は額面。税・社会保険料は扱わない（限界として明記）。
2. **資産残高と年間収支を区別する**：収支はフロー（1 年間の増減）、資産はストック（ある時点の残高）。
3. **購入費用・年間の現金支出・資産価値を区別する**（F-1C）。
4. **赤字・資産不足を 0 に置き換えない**：マイナスのまま記録し、「資産不足の年」として数える。
5. **資金移転を二重計上しない**：親の減少額 = 子の増加額。世帯全体の所得に移転を加えない。
6. **入力データを変更しない**：関数は引数の辞書・リストを書き換えない（`check()` が検出する）。必要なら値を変数にコピーする。
7. **同じ入力から同じ結果**：乱数を使うときは `random.Random(seed)` でシードを固定し、記録する。
8. **時間の制約は 1 人ごとに確かめる**：2 人の合計だけを見ない（F-1B）。
9. **仮定値と統計値を区別する**：データの由来（`synthetic`／出典）を残す。
10. **速度の比較は同じ入力・同じ出力の条件で**：評価指標やモデルを変えた結果の違いを高速化と混同しない。

## 5. 同点・境界の扱い

| 場面 | 規則 |
| --- | --- |
| 予算と価格が等しい | 予算**以下**なので含める |
| 同じ価格の物件 | ソートは安定（元の順番を保つ）。二分探索は「予算以下の最後の位置の次」（upper bound）を返す |
| 該当なし | 空のリスト、または件数 0 |
| 最大値が複数 | 先に現れたもの（入力の順番）を選ぶ |
| 回収できない | 「回収できない」と分かる値（例：`None`）を返す（Phase 3 で決定） |
| 期間 0 年 | 累積額 0、履歴は空のリスト |

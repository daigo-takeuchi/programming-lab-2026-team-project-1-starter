# シミュレーションの規則（全テーマ共通）

Notebook・参照実装（solutions/）・データ辞書は、この規則に合わせてある。

## 1. 単位

| 量 | 単位 | 名前の付け方 |
| --- | --- | --- |
| 金額 | 万円 | 月額は `monthly_`、年額は `annual_`、総額は `purchase_price`・`education_cost` など |
| 年齢 | 歳（整数） | `age`、`start_age`、`retirement_age` |
| 期間 | 年（整数） | `years`、`duration_years` |
| 時間 | 時間／週 | `weekly_` で始める。1 人 168 時間／週 |
| 割合 | 小数（0.02 = 2%） | `annual_growth` |
| 通勤時間 | 分（片道） | `commute_minutes` |
| 床面積 | ㎡ | `floor_area` |

## 2. 時間の流れ（共通）

- シミュレーションの 1 年目は `year = 1`。記録するのは**年の終わり（年末）の状態**。
- 初期状態（`initial_assets`）は `year = 0` に相当し、履歴のリストには含めない。年数 0 なら空のリスト。
- 年齢との対応：`year = t` の年の年齢は「初期の年齢 + t − 1」（その年の初めの年齢）。

## 3. テーマごとの処理の順番

### F-1A

| 項目 | 規則 |
| --- | --- |
| 就業期間 | `start_age ≤ 年齢 < retirement_age`。就業年数 = `max(0, retirement_age − start_age)` |
| 退職年齢 | 関数の**引数**の値を使う（辞書の `retirement_age` は Tiny の候補ごとの値。Notebook では引数に渡して使う） |
| 初年度給与 | `start_age` の年は `initial_salary` |
| 昇給 | 翌年から。年齢 a の年収 = `initial_salary × (1 + annual_growth) ** (a − start_age)` |
| 教育費 | **18 歳の年にまとめて**計上（両方の候補で 18 歳の時点で引く）。生涯所得には含めない |
| 生涯所得 | 就業期間の年収の合計（`lifetime_income`） |
| 累積所得（教育費控除後） | 生涯所得 − 教育費（`net_income`）。税引後所得・資産残高ではない |
| 回収年齢 | 18 歳から順に、2 つの候補の「その年齢までの年収の合計 − 教育費」を比べ、**以上**になる最初の年齢。退職年齢の前の年までに追いつかなければ `None`。18 歳で既に以上なら 18 |

### F-1B

| 項目 | 規則 |
| --- | --- |
| お金 | 年間所得 = 2 人の年収の合計。年間支出 = 生活費 + 育児費 + 介護費。年間収支 = 所得 − 支出（万円／年） |
| 時間の 4 区分（**重ならない**） | 基本生活時間（睡眠・食事・身支度、`basic_hours`、初期値 77）／労働時間（仕事 + 通勤）／育児・介護時間（直接伴う家事を含む）／残り時間（育児・介護以外の家事、休養、自由時間） |
| 1 人の残り時間 | `168 − basic_hours − weekly_work_hours − care`。マイナスなら時間の制約違反 |
| 基本生活時間 | 引数で渡すパラメータ（Notebook の `BASIC_HOURS` を変えられる） |
| 分担 | 分担の候補 `(care_a, care_b)` は教員が与える（Mini：`CARE_SPLITS`、Tiny：`make_care_splits(必要時間)`） |
| 実行可能な計画 | ① 収支 ≥ 0 ② `care_a + care_b ≥ required_childcare_hours + required_eldercare_hours` ③ 2 人それぞれの残り時間 ≥ `min_free_hours` |
| 探索の順 | 組合せ（A の勤務形態の順 → B の順）→ 分担の候補の順 |

### F-1C

| 項目 | 規則 |
| --- | --- |
| 家賃 | 年間家賃 = 月額 × 12。累積家賃 = 年間家賃を年数分足す（0 年は 0） |
| 購入 | 費用 = 購入価格（最初に 1 回）+ 年間維持費 × 年数。ローン・売却価格・資産価値は Level 1・2 で扱わない |
| 比較期間 | 賃貸と購入は同じ年数で比べる |
| 予算の条件 | 価格 ≤ 予算（等しいものを含む）。通勤時間 ≤ 上限 |
| ソート | 価格の安い順、**安定**（同じ価格は入力の順）。元のリストは変えない |
| 二分探索 | ソート済み価格で、予算以下の件数（upper bound）を返す。0〜N |
| 取り出し | 先頭から k 件（価格の順）。線形探索の結果とは**集合**として一致する |

### F-1D

| 項目 | 規則 |
| --- | --- |
| 1 年の順番 | ① 親子それぞれ `資産 + 年収 − 支出` ② `year ≤ duration_years` なら親から子へ `annual_transfer` を移す ③ 年末の資産を記録 |
| 移転 | 親の減少額 = 子の増加額（合計は保存）。家族全体の所得に移転を加えない（二重計上しない） |
| 開始年 | Level 1・2 は 1 年目から（Tiny の `start_year = 1` の行）。`start_year = 3` は Level 3 用 |
| 資産不足 | マイナスのまま記録し、`count_shortage_years` で「下限**より小さい**年」を数える（下限と等しい年は不足ではない） |
| 親の最低生活資金 | 親の年末資産が 1 年でも下限より小さいシナリオは除く |
| 年数 0 | 履歴は空。最後の資産は初期資産 |

## 4. 守ること

1. 所得と可処分所得、資産残高と年間収支、購入費用・年間の現金支出・資産価値を区別する。
2. 赤字・資産不足を 0 に置き換えない。
3. 入力データを変更しない（`check()` が検出する）。同じ入力から同じ結果になる（乱数はシード固定）。
4. 時間の制約は 1 人ごとに確かめる。
5. 仮定値と統計値を区別する（`_tiny` と `_small`、`source` 列）。
6. 速度の比較は同じ入力・同じ結果の条件で行う。

## 5. 同点・境界の扱い

| 場面 | 規則 |
| --- | --- |
| 予算と価格が等しい | 予算以下なので含める |
| 同じ値の候補 | ソートは安定（元の順番）。条件の抽出は入力の順 |
| 該当なし | 空のリスト、件数 0 |
| 回収できない | `None` |
| 期間 0 年・移転期間 0 | 累積額 0、履歴は空／移転しない |

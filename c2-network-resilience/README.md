## 1. 研究テーマと目的

**C2：サイバー攻撃・障害に強いネットワーク構造の設計**

ネットワークを**ノード（頂点）とリンク（辺）からなるグラフ**として表し、スター型・リング型・ランダム型・メッシュ型の4つの構造を比較します。
DFS・BFS による探索を使って、ノードやリンクの障害に対する**耐性（レジリエンス）**を調べます。

| | 問い |
| --- | --- |
| RQ1 | **ネットワーク構造と接続性**：構造によって、接続性や冗長性はどう変わるか（ノード数、リンク数、次数、到達可能性、連結成分、代替経路、リンク密度） |
| RQ2 | **障害・攻撃への耐性**：ノードやリンクが失われたとき、接続性はどう変わるか（ランダム障害、中心ノードの障害、高次数ノードを狙った標的型障害、単一障害点） |
| RQ3 | **DFS・BFS の活用**：到達可能性、障害後の連結性、連結成分の数、最短ホップ数を、DFS・BFS でどう調べるか。両者の探索順序と計算量はどう違うか |

学習段階に応じて、課題を2層に分けています。

- **Core Research（必須課題）**：4種類のネットワーク生成、DFS・BFS、単一障害のシミュレーション、連結性の評価、性能比較
- **Advanced Research（発展課題）**：ランダム障害と標的型障害、スモールワールド・スケールフリー、ネットワーク効率、関節点・橋、コスト制約下の設計

このリポジトリは**完成済みのネットワーク分析システムではありません**。基本となる生成・探索・単一障害の評価だけを用意しています。

## 2. ネットワークとグラフ理論

| 用語 | 意味 | ネットワークでの例 |
| --- | --- | --- |
| ノード（頂点） | つながる対象 | ルーター、サーバー、PC |
| リンク（辺） | 2つのノードのつながり | ケーブル、通信回線 |
| 次数 | 1つのノードにつながっているリンクの数 | そのルーターの接続先の数 |
| 経路 | リンクをたどってノードからノードへ行く道 | 通信の経路 |
| ホップ数 | 経路で通るリンクの数 | 何台の機器を経由するか |
| 連結 | どの2ノード間にも経路がある | 全体が通信できる |
| 連結成分 | 互いに行き来できるノードの最大の集まり | 分断後の「島」 |

この教材では、ネットワークを**重みなし・無向グラフ**として扱います（リンクに距離やコストはなく、どちら向きにも通信できる）。

### 隣接リストによる表現（`network.py`）

```python
graph = {
    0: [1, 2, 3],   # ノード0の隣はノード1, 2, 3
    1: [0],
    2: [0],
    3: [0],
}
```

- 無向グラフなので、`u` の隣接リストに `v` があれば、`v` の隣接リストにも `u` があります（**対称**）。
- **自己ループ**（自分自身へのリンク）や**重複リンク**は作りません。
- リンクを持たない**孤立ノード**も、空のリスト `[]` として辞書に残します。
- 隣接リストは番号の小さい順に並べています（DFS・BFS の訪問順序が毎回同じになる）。

## 3. スター・リング・ランダム・メッシュ

| 構造 | 生成関数 | リンク数（ノード数 n） | 特徴 |
| --- | --- | --- | --- |
| スター型 | `network.star(n)` | n − 1 | 中心ノード0にすべてがつながる。**中心が単一障害点** |
| リング型 | `network.ring(n)` | n（n ≥ 3） | 輪の形。どのリンクも1本切れても迂回できるが、2本切れると分断される |
| ランダム型 | `network.random_graph(n, p, seed)` | 平均 p × n(n−1)/2 | すべてのノードの組を確率 p でつなぐ。**連結になるとは限らない** |
| メッシュ型 | `network.mesh(rows, cols)` | rows(cols−1) + cols(rows−1) | 2次元格子。上下左右の隣とつながる |

```text
スター型（6ノード）    リング型（6ノード）    メッシュ型（3×3）
    1   2              0 -- 1 -- 2          0 -- 1 -- 2
     \ /               |         |          |    |    |
  5 - 0 - 3            5 -- 4 -- 3          3 -- 4 -- 5
      |                                     |    |    |
      4                                     6 -- 7 -- 8
```

- **ランダム型**は、乱数シード `seed` を指定すると、毎回同じネットワークが生成されます（再現可能）。生成されたネットワークが**連結になるとは限りません**。`starter.py` の `seed=6` の例では、ノード2・6だけが残りから切り離されています。
- **メッシュ型は完全グラフとは異なります。** この教材のメッシュ型は「格子状」で、隣どうしだけがつながります。すべてのノードどうしを直接つなぐ**完全グラフ（完全メッシュ）**では、リンク数は n(n−1)/2 になります（3×3 = 9ノードなら、格子は12本、完全グラフは36本）。完全メッシュとの比較は Advanced Research で扱ってかまいません。
- 境界条件：ノード数0なら `{}`、1なら `{0: []}`。リング型の n = 2 は、重複リンクを作らないためリンク1本になります。

## 4. DFS と BFS

### DFS（深さ優先探索）：`traversal.dfs(graph, start)`

行けるところまで深く進み、進めなくなったら戻って別の道を探します。

1. 開始ノードを**スタック**に積む。
2. スタックからノードを取り出し、未訪問なら訪問済みにする。
3. その隣接ノードのうち未訪問のものをスタックに積む（番号の小さい隣から訪問するよう、逆順に積む）。
4. スタックが空になるまで 2〜3 を繰り返す。

戻り値は、訪問した順のノードのリストです。

### BFS（幅優先探索）：`traversal.bfs(graph, start)`

開始ノードに近い順（1ホップ、2ホップ、…）に調べます。

1. 開始ノードを**キュー**に入れる（ホップ数0）。
2. キューからノードを取り出す。
3. 未訪問の隣接ノードを、ホップ数 +1 としてキューに入れる。
4. キューが空になるまで 2〜3 を繰り返す。

戻り値は `(訪問順のリスト, {ノード: 最短ホップ数})` です。**重みなしグラフでは、BFS で求めたホップ数が最短**になります。

### DFS と BFS の比較

| | DFS | BFS |
| --- | --- | --- |
| 使うデータ構造 | スタック（または再帰） | キュー |
| 訪問の順序 | 深い方へ進んでから戻る | 近い順 |
| 到達可能なノードの集合 | 同じ | 同じ |
| 最短ホップ数 | 求められない（一般に） | 求められる |
| 時間計算量（隣接リスト） | O(V + E) | O(V + E) |

- V はノード数、E はリンク数です。各ノードを1回訪問し、各リンクを両方向から1回ずつ調べるため、**O(V + E)** になります。
- **訪問順序は、隣接ノードを並べる順序によって変わります。** 例えばメッシュ型 3×3 でノード0から探索すると、DFS は `[0, 1, 2, 5, 4, 3, 6, 7, 8]`、BFS は `[0, 1, 3, 2, 4, 6, 5, 7, 8]` になりますが、隣接リストの順序を変えると別の順序になります。
- この教材の DFS は、スタックに同じノードが複数回積まれることがある（訪問済みかどうかは取り出したときに調べる）ため、スタックへの push は最大 2E + 1 回です。BFS はキューへの追加がちょうど V 回です。**同じ O(V + E) でも、実装の細部によって実測時間は変わります。**

## 5. ノード障害・リンク障害（`resilience.py`）

| 関数 | 内容 |
| --- | --- |
| `remove_node(graph, node)` | **ノード障害**：ノードと、そのノードにつながるリンクを取り除いた新しいグラフを返す |
| `remove_edge(graph, u, v)` | **リンク障害**：リンク `u -- v` を両方向とも取り除いた新しいグラフを返す（ノードは残る） |

どちらも**元のグラフは変更しません**。障害の前後を比較できるようにするためです。

障害の種類（RQ2）：

- **ランダムなノード障害・リンク障害**：機器の故障や停電などをイメージしたモデル
- **中心ノードの障害**：スター型の中心など、多くのノードが依存するノードの障害
- **高次数ノードを狙った標的型障害**：次数の高いノードから順に失われるモデル（Advanced A）
- **単一障害点（SPOF：Single Point of Failure）**：それ1つが失われるだけで、ネットワークが分断されるノードやリンク

## 6. ネットワークの連結性

| 関数 | 内容 |
| --- | --- |
| `connected_components(graph)` | 連結成分のリスト（BFS を使って、まだどの成分にも入っていないノードから順に調べる） |
| `is_connected(graph)` | 連結成分がちょうど1つなら `True`（ノードが1つもない場合は `False`） |
| `largest_component_size(graph)` | 最大連結成分のノード数 |
| `largest_component_ratio(graph, total_nodes)` | 最大連結成分のノード数 ÷ `total_nodes` |

`starter.py` の単一障害の比較結果：

| 構造 | 障害 | 障害後の連結性 | 連結成分数 | 最大連結成分 | 割合A（÷障害前） | 割合B（÷障害後） |
| --- | --- | --- | ---: | ---: | ---: | ---: |
| スター型（6） | 中心ノード0 | 非連結 | 5 | 1 | 0.17 | 0.20 |
| スター型（6） | 末端ノード5 | 連結 | 1 | 5 | 0.83 | 1.00 |
| リング型（6） | リンク 0--1 | 連結 | 1 | 6 | 1.00 | 1.00 |
| メッシュ型（3×3） | リンク 4--5 | 連結 | 1 | 9 | 1.00 | 1.00 |

## 7. 耐障害性の評価指標

### 最大連結成分の割合：分母に注意

`largest_component_ratio()` の分母は、呼び出す側が決めます。**どちらを使ったかを必ず明記してください。**

- **割合A：障害前のノード数で割る** → 失われたノードの影響も含めて評価できる。「元のネットワークのうち、どれだけが1つにつながったまま残ったか」。
- **割合B：障害後に残ったノード数で割る** → 残ったノードどうしのつながりだけを評価する。

例えば、スター型の末端ノード5が失われた場合、残りの5ノードはすべて連結なので割合B = 1.00 ですが、割合A = 5/6 ≒ 0.83 です。

### その他の指標

| 指標 | 内容 |
| --- | --- |
| 連結か | 全体が1つにつながっているか |
| 連結成分数 | 分断された「島」の数 |
| 最大連結成分のサイズ・割合 | 最も大きな島のノード数とその割合 |
| リンク密度 | リンク数 ÷ (n(n−1)/2)。完全グラフなら1 |
| 次数・次数分布 | `network.degrees()`。高次数ノードは障害時の影響が大きい |
| 最短ホップ数・平均最短経路長 | BFS で計算（Advanced C） |
| 単一障害点の数 | 1つ失われるだけで分断されるノード（関節点）・リンク（橋）の数（Advanced D） |

## 12. Advanced Research：発展課題

必須課題を終えたチームが挑戦する課題です。**Advanced A〜E のうち、チームの能力と時間に応じて1つ以上を選択**してください。すべてを実装する必要はありません。

Advanced Research では、必要に応じて **NetworkX** や **Matplotlib** を使ってもかまいません。ただし、DFS・BFS の仕組みを理解することを優先し、**探索処理をライブラリに丸投げしない**でください（自分たちの実装の結果と、ライブラリの結果を照合するのはよい使い方です）。

### Advanced A：ランダム障害と標的型障害の比較

**目的**：障害の発生のしかたによって、ネットワークの耐性がどう変わるかを調べる。

1. ランダムにノードを削除する。
2. **次数の高いノードから**削除する。
3. ランダムにリンクを削除する。
4. 障害率（削除する割合）を段階的に増やす。
5. 最大連結成分の割合を比較する。
6. 複数回の乱数実験を行う（乱数シードを記録する）。
7. 平均値とばらつき（標準偏差など）を評価する。

> 高次数ノードの削除は、**抽象的な標的型障害モデル**であり、実際の攻撃方法を再現するものではありません。
> 次数を「最初に1回だけ計算する」か「削除のたびに計算し直す」かで結果が変わります。どちらを使ったか明記してください。

### Advanced B：スモールワールド・スケールフリーネットワーク

**目的**：現実の通信ネットワークに近い特徴を持つ構造を調べる。

1. **Watts–Strogatz モデル**（スモールワールド：規則的な構造の一部をランダムにつなぎ替える）を調査する。
2. **Barabási–Albert モデル**（スケールフリー：次数の高いノードほど新しいリンクを得やすい）を調査する。
3. スター・リング・ランダム・メッシュとの違いを比較する。
4. 次数分布を調べる。
5. 平均最短経路長を調べる。
6. ランダム障害と標的型障害への耐性を比較する。

必要に応じて NetworkX を使ってもかまいません（Core Research では使わない）。

### Advanced C：ネットワーク効率と代替経路

**目的**：単純な接続性だけでなく、障害後の通信効率を評価する。

1. BFS でノード間の最短ホップ数を求める。
2. 平均最短経路長を計算する。
3. 障害前後の最短経路長を比較する。
4. 代替経路の有無を調べる。
5. ネットワーク効率を評価する。
6. **接続性が維持されても、通信経路が長くなる**場合を分析する（例：リング型でリンクを1本切ると、隣のノードへの経路が最大 n−1 ホップになる）。

> **非連結グラフでは、平均最短経路長の定義に注意してください。**
> - 到達可能なノードの組だけで平均する方法（到達できない組は除外）
> - 到達できない組の距離を ∞ とみなし、1/距離 の平均（**ネットワーク効率**、到達不能な組は 0 として数える）を使う方法
> この2つを区別し、どちらを使ったか明記してください。

### Advanced D：関節点・橋・冗長性の分析

**目的**：ネットワークの弱点となるノードやリンクを特定する。

1. **関節点（Articulation Point）**：取り除くと連結成分が増えるノード
2. **橋（Bridge）**：取り除くと連結成分が増えるリンク
3. ノードを1つ削除したときの連結性を比較する。
4. リンクを1つ削除したときの連結性を比較する。
5. 弱点となるノード・リンクを特定する。
6. リンクを追加して耐障害性を改善する。
7. 追加リンク数と改善効果の関係を分析する。

まずは「1つずつ取り除いて `is_connected()` を調べる」素朴な方法（計算量を考えてみよう）から始め、発展的には **Tarjan のアルゴリズム**（DFS を1回行うだけで関節点・橋を求める）を調査してください。このリポジトリには、関節点・橋の検出アルゴリズムは実装していません。

### Advanced E：コスト制約下でのネットワーク設計

**目的**：限られたリンク数や設備コストの中で、耐障害性の高いネットワークを設計する。

1. 各リンクに仮想的なコスト（距離に比例する など）を設定する。
2. 総リンク数または総コストに上限を設定する。
3. 追加リンクの候補を比較する。
4. 耐障害性が最も改善するリンクを選ぶ。
5. コストと耐障害性のトレードオフを分析する。

> リンクを増やすほど耐障害性は上がりますが、コストも増えます。**単純なメッシュ型（や完全グラフ）が常に最適とは限らない**ことを考察してください。

## 13. 実験条件と評価指標

### 記録すべき実験条件

- PC 環境（CPU、メモリ）、OS、Python のバージョン
- ネットワークの種類とパラメータ（ノード数、p、rows × cols など）、乱数シード
- 障害の種類（ノード／リンク、ランダム／標的型）と障害率
- 最大連結成分の割合の分母
- 測定回数と、平均値・中央値・標準偏差などの集計方法

### 評価指標

| 指標 | 内容 |
| --- | --- |
| 処理時間 | DFS・BFS・障害の評価の時間を `time.perf_counter()` で測る（生成・表示の時間は含めない） |
| 連結性・連結成分数・最大連結成分の割合 | 6・7章 |
| 平均最短経路長・ネットワーク効率 | Advanced C |
| 関節点・橋の数 | Advanced D |
| コスト | Advanced E |

### 注意

- ランダム型や障害の実験は、乱数によって結果がばらつきます。**複数回実験**し、平均とばらつきを示してください。
- 大きなネットワークでは、すべてのノードの組の最短経路を求めると時間がかかります（BFS を V 回行うと O(V(V + E))）。
- `network.random_graph()` はすべてのノードの組（n(n−1)/2 組）について乱数を引くため、**生成に O(n²) の時間**がかかります。ノード数が数万になると生成だけで時間がかかるので、生成時間と探索時間を分けて測ってください。
- Big-O は漸近的な評価であり、実測時間そのものではありません。

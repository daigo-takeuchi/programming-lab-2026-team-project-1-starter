## 1. F5 の研究テーマ

身近な問題、社会の仕組み、情報処理、ゲーム、生活、教育、交通、経済など、**関心のある分野から研究テーマを自由に設定**します。Python で問題解決のアルゴリズムを実装し、比較・評価します。

研究内容はチームが決めます。ただし、次の 8 つは**必須要件**です（5 章）。

1. 明確な研究課題（Research Question）を設定する。
2. 探索・ソート・スタック・キュー・再帰などのアルゴリズムから、**2 種類以上を実装・使用する**。
3. 少なくとも 1 つの共通課題に対して、**2 種類以上のアルゴリズムを比較評価する**。
4. 各アルゴリズムの理論的な時間計算量を説明する。
5. 入力サイズや問題の条件を変えて、実行時間などを測定する。
6. 計算結果の正しさを検証する。
7. 比較結果を表やグラフで示す。
8. 結果を考察し、アルゴリズムの長所・短所を説明する。

## 2. 自由研究の目的

自分で研究テーマを選び、アルゴリズムを使って問題を解決する過程を学びます。

- 問題を明確に定義する
- 入力と出力を決める
- アルゴリズムを選ぶ
- Python で実装する
- 複数の方法を比較する
- 計算結果を検証する
- 計算量を分析する
- 実験条件をそろえる
- 結果を可視化する
- 結果の理由を考察する
- 研究成果を発表する

**アプリケーションや Web サイトを作るだけで終わらないでください。**アプリを作る場合も、その中で使うアルゴリズムを研究対象としてはっきりさせ、比較・評価してください。

## 3. 研究テーマの選び方

1. **身近な「探す・並べる・順番を決める・道を選ぶ・数える」場面**を探す（図書館、買い物、通学路、ゲーム、予定表、行列など）。
2. それを**入力と出力**がある問題に言い換える。
3. その問題を解く**アルゴリズムが 2 つ以上**考えられるか確かめる。
4. **入力サイズ N** を変えられるか確かめる（データを生成できるか、公開データがあるか）。
5. 3〜4 週間で実装・実験・発表できる大きさに絞る。

## 4. Research Question の設定

よい Research Question には、**比べるもの・条件・指標**が入っています。

| よくない例 | よい例 |
| --- | --- |
| 二分探索は速いか？ | N = 100・1,000・10,000 のとき、ソートの前処理を含めても二分探索が線形探索より速くなるのは、何回以上探索する場合か |
| 迷路を解くプログラムを作る | 迷路の大きさと壁の割合を変えたとき、DFS と BFS で、探索したマスの数と見つけた経路の長さはどう違うか |
| メモ化はすごい | フィボナッチ数の計算で、単純な再帰とメモ化した再帰の呼び出し回数と実行時間は、n とともにどう増えるか |

- **仮説は実験の前に書きます**。あとから結果に合わせて書き換えないでください。
- 研究計画は、`docs/research_plan.md` と `notebooks/01_research_question.ipynb` に書きます。

## 6. アルゴリズムとは何か

アルゴリズムとは、**問題を解くための、はっきり決められた手順**です。

- **入力**を受け取り、**出力**を返す。
- 有限の手順で**必ず終わる**。
- どの手順も**あいまいさがない**。
- 同じ問題にも、複数のアルゴリズムがある。アルゴリズムによって、**速さ・必要なメモリ・前提条件・解の品質**が違う。

このため、「どのアルゴリズムを、どんな場面で使うべきか」が研究の対象になります。

## 7. 探索アルゴリズム

| アルゴリズム | 考え方 | 前提条件 | 最悪の時間計算量 | 教科書 |
| --- | --- | --- | --- | --- |
| 線形探索 | 先頭から順に調べる | なし | O(N) | 第3章 `ssearch_while.py` ほか |
| 番兵法 | 末尾に探す値を置き、終了判定を減らす | 末尾に 1 つ追加できる | O(N) | 第3章 `ssearch_sentinel.py` |
| 二分探索 | 中央と比べて範囲を半分にする | **ソート済み** | O(log N) | 第3章 `bsearch.py` |
| ハッシュ法 | ハッシュ値で格納場所を決める | ハッシュ関数 | 平均 O(1)、最悪 O(N) | 第3章 `chained_hash.py`・`open_hash.py` |
| 文字列探索 | 力まかせ法・KMP 法・Boyer-Moore 法 | — | 力まかせ法 O(NM) など | 第7章 |
| 2 分探索木 | 木をたどって探す | 木の形による | 平均 O(log N)、最悪 O(N) | 第9章 |

二分探索は、**探索の対象がソート済みでないと正しく動きません。**ソートの前処理コスト O(N log N) を無視しないでください（12 章）。

## 8. ソートアルゴリズム

| アルゴリズム | 最良 | 平均 | 最悪 | 安定 | 教科書（第6章） |
| --- | --- | --- | --- | --- | --- |
| 単純交換（バブル）ソート | O(N)※ | O(N²) | O(N²) | ○ | `bubble_sort1.py`〜`3.py` |
| 単純選択ソート | O(N²) | O(N²) | O(N²) | × | `selection_sort.py` |
| 単純挿入ソート | O(N) | O(N²) | O(N²) | ○ | `insertion_sort.py` |
| シェルソート | — | 間隔の選び方による | — | × | `shell_sort1.py`・`2.py` |
| クイックソート | O(N log N) | O(N log N) | O(N²) | × | `quick_sort1.py` ほか |
| マージソート | O(N log N) | O(N log N) | O(N log N) | ○ | `merge_sort.py` |
| ヒープソート | O(N log N) | O(N log N) | O(N log N) | × | `heap_sort.py` |
| 度数ソート | O(N + K) | O(N + K) | O(N + K) | ○ | `counting_sort.py`（K：値の範囲） |

※ 交換が起きなければ打ち切る改良版の場合。

**入力の並び**（ランダム、ほぼ整列済み、逆順、同じ値が多い）によって、実行時間が大きく変わるアルゴリズムがあります。実験の条件にしてみましょう。

## 9. スタックとキュー

| データ構造 | 取り出す順 | 主な操作 | 計算量 | 教科書（第4章） |
| --- | --- | --- | --- | --- |
| スタック | 後入れ先出し（LIFO） | push・pop | 通常 O(1) | `fixed_stack.py`・`stack.py` |
| キュー | 先入れ先出し（FIFO） | enqueue・dequeue | リングバッファや deque なら O(1) | `fixed_queue.py`・`queue.py` |
| 優先度付きキュー | 優先度の高い順 | 追加・最小値の取り出し | ヒープなら O(log N) | 第6章 `heap_sort.py`（ヒープ） |

キューの実装方法による違いに注意してください。Python の `list.pop(0)` は先頭を取り除くたびに要素をずらすので、**O(N)** かかります。このような**実装による計算量の違い**も研究テーマになります。

## 10. 再帰アルゴリズム

- 関数が自分自身を呼び出して、問題を小さな同じ形の問題に分けます。**終了条件**（基底）が必要です。
- 教科書第5章：階乗（`factorial.py`）、最大公約数（`gcd.py`）、ハノイの塔（`hanoi.py`）、8 王妃問題（`8queen*.py`）、メモ化（`recur_memo.py`）。
- 単純な再帰では、同じ計算を何度もくり返すことがあります（例：フィボナッチ数で O(2^n) 程度）。**メモ化**すると O(n) に減らせます。
- Python の再帰には深さの上限があります（既定で約 1,000）。大きな入力では、`RecursionError` やループへの書き換えを考えてください。

| アルゴリズム | 考え方 | 例 |

| Greedy 法 | その場で最も良い選択をくり返す | おつり、区間スケジューリング |

## 12. 複数アルゴリズムの比較

### 比べるときの約束

- **同じ問題を解く**アルゴリズムどうしを比べる。
- **入力データと実験条件をそろえる**（同じデータ、同じシード、同じ入力サイズ、同じ環境）。
- アルゴリズムごとに解く問題や入力条件が違う場合は、**直接の性能比較はできない**ことを説明する。
- **前提条件・前処理**の違いをはっきりさせる。初期デモでは、二分探索のためのソートの時間を、**含めない比較**（探索だけ）と**含める比較**（ソート + 探索）に分けています。
- **性質が違うアルゴリズム**は、時間だけでなく、解の品質や探索の目的も比べる。
  - 例：DFS と BFS はどちらも経路を探しますが、BFS は無重みグラフで**最短経路を保証**し、DFS は保証しません。
  - この場合は、「探索したノード数」「見つけた経路の長さ」「実行時間」を並べて比べます。

### 比較の仕組み（`experiments/compare_algorithms.py`）

`run_comparison(task, sizes, repeat, warmup, seed)` は、入力サイズ N ごとに次の 5 段階を実行します。

| 段階 | 内容 | 記録する値 |
| --- | --- | --- |
| 1. 入力データを作る | 同じ N のアルゴリズムには、すべて同じ入力を使う | `gen_s` |
| 2. 前処理 | アルゴリズムごとの前処理（例：ソート） | `prep_s` |
| 3. 実行 | repeat 回測った中央値 | `run_s` |
| 4. 結果の検証 | 結果が正しいか | `correct`・`verify_s` |
| 5. 答えの比較 | アルゴリズムどうしで答えが一致するか | `consistent` |

比較回数のように、実行環境によらない指標も数えられます（`operations`）。

```bash
python3 -m experiments.compare_algorithms                          # N = 100, 1,000, 10,000
python3 -m experiments.compare_algorithms --sizes 1000 5000 20000 --repeat 7
python3 -m experiments.compare_algorithms --hit-ratio 0 --order sorted   # 入力の特徴を変える（最悪ケースなど）
python3 -m experiments.compare_algorithms --csv results/search.csv       # CSV に保存（任意）
```

### 研究テーマを変更する方法

比較の手順（`run_comparison`）は、課題によらず使えます。テーマを変えたら、次の手順で置き換えます。

1. **アルゴリズムを書く**
   - `algorithms/` に新しいファイルを作る（例：`algorithms/dfs.py`・`algorithms/bfs.py`）。`algorithm_a.py`・`algorithm_b.py` を書き換えてもかまいません。
   - 各ファイルに `NAME`・`PRECONDITION`・`COMPLEXITY` と、入力・出力の説明を書きます。
2. **課題（task）を作る**：`make_search_task` と同じ形の辞書を作ります。

   ```python
   task = {
       "name": "maze",
       "description": "N × N の迷路でスタートからゴールまでの経路を探す",
       "make_input": lambda n, seed: make_maze(n, seed),          # 入力サイズ n とシードから入力を作る
       "algorithms": [
           {"key": "A", "label": "A: DFS", "prepare": None, "run": lambda _p, inp: dfs(inp), "count": None},
           {"key": "B", "label": "B: BFS", "prepare": None, "run": lambda _p, inp: bfs(inp), "count": None},
       ],
       "verify": lambda inp, _p, result: path_is_valid(inp, result),   # 経路が実際に存在するか
       "answer": lambda inp, _p, result: result is not None,            # アルゴリズム間で比べる答え（例：到達できたか）
   }
   rows = run_comparison(task, sizes=(10, 20, 40), repeat=5)
   ```

   - 入力を書き換えるアルゴリズム（例：その場でソートする）には `"mutates": True` を付けます。測定ごとに入力をコピーし、コピーの時間は測定値に含めません。
   - 答えが 1 つに決まらない問題（例：DFS の経路）では、`answer` に**共通の評価基準**（到達できたか、経路の長さなど）を返させます。
3. **テストを追加する**：`tests/` に、新しいアルゴリズムのテストを**必ず追加**します。正しい結果・空の入力・境界条件・不正な入力・アルゴリズム間の一致を確かめます。初期デモのテストは、デモを削除したら一緒に削除してかまいません。
4. **Notebook を差し替える**：02〜04 の import と task を差し替えます（`notebooks/README.md`）。
5. **README を書き換える**：「初期デモ」の説明を、チームの研究の説明に書き換えます。

## 13. 計算量

計算量は、**入力サイズ N が増えたときに、手間がどのように増えるか**を表します（O 記法）。

- **N の意味を必ず書きます**（例：データの要素数、迷路のマスの数 V と通路の数 E）。
- 最良・平均・最悪の時間計算量と、空間計算量（追加で必要なメモリ）を区別します。最悪の場合を中心に扱ってかまいません。
- 計算量は、**前提条件やデータ構造によって変わります**（例：キューを `list.pop(0)` で作ると O(N)、`deque` なら O(1)）。

| アルゴリズム | 代表的な時間計算量 |
| --- | --- |
| 線形探索 | O(N) |
| 二分探索 | O(log N)（ソート済みが前提。ソートは O(N log N)） |
| 選択ソート | O(N²) |
| 挿入ソート | 最悪 O(N²)（ほぼ整列済みなら O(N) に近い） |
| マージソート | O(N log N) |
| スタックの push/pop | 通常 O(1) |
| キューの enqueue/dequeue | 適切な実装では通常 O(1) |
| DFS | O(V + E) |
| BFS | O(V + E) |

### 初期デモの計算量

| アルゴリズム | N | 最良 | 平均 | 最悪 | 空間 | 前処理 |
| --- | --- | --- | --- | --- | --- | --- |
| A：線形探索 | データの要素数 | O(1) | O(N) | O(N) | O(1) | なし |
| B：二分探索（最初の位置を返す版） | データの要素数 | O(log N) | O(log N) | O(log N) | O(1) | ソート O(N log N)、追加の空間 O(N)（ソート済みのコピー） |

Q 回探索する場合の比較：

- 線形探索：O(QN)
- 二分探索：O(N log N + Q log N)

Q が小さいと線形探索の方が速く、Q が大きいと二分探索の方が有利になります。どこで逆転するかを実測で確かめることも、研究になります。

**理論計算量と実測時間は別のものです。**計算量は増え方を表し、秒数そのものではありません。N が小さいときは、定数倍や Python の処理のオーバーヘッドが目立つので、理論どおりにならないことがあります。

## 14. 実行時間の測定

`experiments/benchmark.py`：

| 関数 | 役割 |
| --- | --- |
| `measure(func, args, repeat, warmup, number, setup)` | 実行時間を repeat 回測る。中央値・最小・最大・平均を返す |
| `benchmark(func, args, verify=..., ...)` | 結果を `verify` で確かめてから測る。正しくなければ `AssertionError` |
| `timed(func, *args)` | 1 回だけ実行して、(結果, 秒) を返す。データ生成・前処理・検証の時間に使う |
| `median(values)` | 中央値 |
| `autorange(func, ...)` | 1 回の測定が一定時間以上になる呼び出し回数を決める |

### 測定の約束

- 時間は **`time.perf_counter()`** で測ります。
- 測定は **repeat 回くり返し**、代表値には**中央値**を使います（外れ値に強いため）。最小〜最大も一緒に報告します。
- **warmup**（慣らし運転）の回数は、測定値に含めません。
- **とても短い処理**は、1 回の測定の中で `number` 回呼び出して、1 回あたりの時間に直します（`number="auto"`）。
- **入力を変更するアルゴリズム**には、`setup` で毎回新しいコピーを渡します。コピーの時間は**測定値に含めず**、`setup_median` として別に記録します。
- **4 つの時間を区別**し、比較の目的に応じて、どの時間を比べるかを明記します。
  - 入力データの生成時間
  - 前処理の時間
  - アルゴリズムの実行時間
  - 結果の検証時間
- 実測時間は、**実行環境**（CPU、OS、Python のバージョン、他のプログラム、Colab かローカルか）の影響を受けます。同じ環境・同じ実行の中で比べ、`docs/experiment_log.md` に実行環境を記録します。
- **実測していない数値を、結果として書かないでください。**

## 15. 正しさの検証

性能を比べる前に、**結果が正しいこと**を確かめます。正しくないアルゴリズムの速さを比べても意味がありません。

| 確かめること | 例 |
| --- | --- |
| ソートの結果が昇順になっている | `all(a[i] <= a[i + 1] ...)`、元のデータと同じ要素か |
| 探索の結果が正しい | 見つかった位置の値が key と等しい。-1 なら本当に含まれない |
| 経路が実際に存在する | 隣り合うマスだけを通り、壁を通らない |
| BFS が無重みグラフで最短経路を返す | 全探索などで求めた最短の長さと一致する |
| スタック・キューの処理順序 | push した順と逆（LIFO）、入れた順（FIFO） |
| 再帰の終了条件 | 最小の入力で正しく止まる |

検証の方法：

- **同じ出力が期待される**アルゴリズムでは、**結果が一致する**ことを確かめます（初期デモ：ソート済みの同じ配列なら、A と B は同じ添字を返す）。
- **異なる解が許される**問題では、**共通の評価基準**を用意します（例：経路の長さ、制約を満たすか）。
- 信頼できる**基準（オラクル）**と照合します（例：Python の `in`・`sorted()`）。
- **境界条件**（空の入力、1 要素、先頭・末尾、同じ値が複数）と**不正な入力**もテストします。

## 22. 実験条件と評価指標

### 実験条件をそろえる

- **同じ入力**（同じデータ・同じシード）、**同じ入力サイズ**、**同じ実行環境**で比べる。
- 入力サイズは、例として **N = 100・1,000・10,000** を使います。研究テーマに合わせて変えてかまいません（迷路なら一辺の長さ、グラフなら頂点数など）。
- 各条件で**複数回**測る（repeat 5 回以上、warmup 1 回以上を推奨）。代表値は**中央値**。
- **どの時間を測ったか**（生成・前処理・実行・検証）を明記する。
- **入力データの特徴**（ランダム、整列済み、逆順、重複が多い、最悪ケース）も条件として書く。

### 評価指標の例

| 指標 | 説明 |
| --- | --- |
| 実行時間 | 中央値と最小〜最大（実行環境に依存する） |
| 操作回数 | 比較回数・交換回数・探索ノード数など（実行環境によらない） |
| 解の品質 | 経路の長さ、待ち時間、公平性など（答えが 1 つに決まらない問題） |
| メモリ使用量 | 追加で必要なメモリ（Advanced） |
| 正しさ | テストの結果、アルゴリズム間の一致 |

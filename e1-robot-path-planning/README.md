## 1. 研究テーマと目的

**E1：自律移動ロボットの経路探索アルゴリズム**

障害物のある2次元マップ上を移動する自律移動ロボットを想定し、**DFS（深さ優先探索）・BFS（幅優先探索）・A\* 探索について、経路長・探索時間・探索ノード数を比較し、マップの構造や障害物の配置による違いを分析する**ことが中心課題です。

| | 問い |
| --- | --- |
| RQ1 | **DFS・BFS・A\* で得られる経路はどう異なるか**：到達できるか、経路長、経路のセル数、展開ノード数、実行時間 |
| RQ2 | **最短経路を求められるのはどのアルゴリズムか**：4方向・移動コスト1の条件で、DFS・BFS・A\* を検証する |
| RQ3 | **障害物の配置は探索効率にどう影響するか**：障害物が少ない／多い、狭い通路、行き止まりが多い、到達不能 |
| RQ4 | **マップ規模と計算量の関係**：幅 W、高さ H、障害物数、スタートとゴールの距離、探索対象セル数（V と E） |

学習段階に応じて、課題を2層に分けています。

- **Core Research（必須課題）**：4方向移動・移動コスト1のグリッドで、DFS・BFS・A\*（マンハッタン距離）を比較する
- **Advanced Research（発展課題）**：障害物密度、ヒューリスティックの比較、8方向移動、動的障害物、実機ロボットへの応用

このリポジトリには、DFS・BFS・A\* の基本的な実装と小さなサンプルマップ3つだけを用意しています。**ランダムマップの生成、繰り返し実験、グラフ化、発展課題の実装は学生の課題**です。

## 2. 自律移動ロボットの経路探索

掃除ロボット、倉庫の搬送ロボット、配膳ロボットなどの自律移動ロボットは、「今いる場所から目的地まで、障害物にぶつからずに行く道」を自分で決める必要があります。これを**経路計画（path planning）**といいます。

実際のロボットでは、地図の作成、自己位置の推定、障害物の検出、モーターの制御など多くの処理が必要ですが、この研究ではその中心にある**「地図の上で道を探す」部分**だけを取り出して調べます。

Core Research では、次のように問題を単純化します。

- 地図は**2次元のマス目（グリッド）**で、各セルは「通れる」か「障害物」のどちらか
- ロボットは**上下左右の4方向**に1セルずつ移動する（斜め移動はしない）
- 1回の移動のコストはすべて **1**
- ロボットの大きさ・向き・速度・加速度・センサーの誤差は考えない

## 3. 2次元グリッドマップ

### マップファイル（`data/*.txt`）

| 記号 | 意味 |
| --- | --- |
| `.` | 通行可能セル |
| `#` | 障害物（進入できない） |
| `S` | スタート（ちょうど1つ） |
| `G` | ゴール（ちょうど1つ） |

```text
##########
#S.......#
#.####...#
#....#...#
#..#.....#
#.....G..#
##########
```

### 座標

セルの座標は **`(row, col)`** で表します。row は上から 0, 1, 2, …、col は左から 0, 1, 2, … です。上の例では `start = (1, 1)`、`goal = (5, 6)` です。

### `grid_map.py` の関数

| 関数 | 内容 |
| --- | --- |
| `load_map(path)`、`parse_map(text)` | マップの読み込みと検証。不正なら `MapError`（`ValueError` の一種） |
| `GridMap` | `rows`（各行の文字列）、`width`（W）、`height`（H）、`start`、`goal` |
| `in_bounds`、`is_obstacle`、`is_passable` | マップの内側か、障害物か、進入できるか（マップの外は進入できない） |
| `neighbors(grid_map, cell)` | 1回の移動で行ける通行可能セル（**上 → 右 → 下 → 左** の固定順） |
| `passable_cells(grid_map)` | 通行可能セルの一覧（グラフのノード集合 V） |
| `count_edges(grid_map)` | 隣り合う通行可能セルの組の数（グラフのエッジ数 E） |
| `is_valid_path(grid_map, path)` | 経路が S から G まで、障害物を通らず、上下左右に1マスずつ進んでいるか |

### 入力検証

読み込み時に次を確認し、満たさなければ `MapError` を送出します。

- マップが空でない（高さ・幅が 0 でない）
- すべての行の長さが同じ
- `.` `#` `S` `G` 以外の文字を含まない（空白も不可）
- スタートとゴールがちょうど1つずつ

S・G は1文字で1つのセルを表すので、スタート・ゴールが障害物と重なることはありません。マップの周囲に壁がなくても、`neighbors` はマップの外のセルを返しません。空行（ファイル末尾の改行など）は無視します。

## 4. グラフ探索の基礎

グリッドマップは**グラフ G = (V, E)** と考えることができます。

| 用語 | グリッドマップでの意味 |
| --- | --- |
| ノード（頂点）V | 通行可能セル（S・G を含む） |
| エッジ（辺）E | 上下左右に隣り合う2つの通行可能セルの組（移動できる関係） |
| 経路 | S から G まで、隣り合うセルをたどった列 |
| 経路長 | 経路での**移動回数**（= セル数 − 1） |

3つのアルゴリズムは、どれも同じ骨組みで動きます。

1. スタートを「これから調べるセルの入れ物」に入れる
2. 入れ物からセルを1つ取り出す。ゴールなら終了
3. そのセルの隣接セルのうち、まだ訪れていないものを入れ物に入れる（どのセルから来たか＝**親**を記録）
4. 入れ物が空になるまで 2〜3 を繰り返す（空になったら到達不能）

**入れ物の種類によって、探索の順序が変わります。**

| アルゴリズム | 入れ物 | 取り出す順序 |
| --- | --- | --- |
| DFS | スタック（LIFO） | 最後に入れたもの（深く進む） |
| BFS | キュー（FIFO） | 最初に入れたもの（近い順に広がる） |
| A\* | 優先度付きキュー | f(n) = g(n) + h(n) が最小のもの |

ゴールに着いたら、ゴールから**親をたどって**スタートまで戻り、逆順にすると経路が得られます（`search._reconstruct`）。

## 5. DFS（深さ優先探索）

`search.dfs(grid_map)`

- **スタック**（教科書 第4章の `FixedStack`）を使い、行けるところまで深く進み、行き止まりになったら引き返します。
- スタックの要素は `(セル, 1つ前のセル)` です。**訪問済みの印は取り出したときに付けます**。同じセルが複数回スタックに入ることがありますが、2回目以降に取り出したものは読み飛ばし、展開しません。
- スタックは後から入れたものを先に取り出すので、**上・右・下・左の順に調べるために、逆順（左・下・右・上）に push** しています。push 順と探索順が逆になる点に注意してください。
- `FixedStack` は容量が固定です。push の回数は「スタートの1回 + 展開した各セルから最大4回」なので、容量を **1 + 4V** にして満杯にならないようにしています。

> **DFS は、到達可能なら必ず経路を見つけますが、最短経路を保証しません。**
> サンプルマップでも、`simple_map.txt` で BFS の 9 に対して DFS は 19、`maze_map.txt` で 50 に対して 78 の経路を返します。
> DFS の結果は、隣接セルを調べる順序（`grid_map.DIRECTIONS`）によって大きく変わります。

## 6. BFS（幅優先探索）

`search.bfs(grid_map)`

- **FIFO キュー**（教科書 第4章の `FixedQueue`）を使い、スタートから近いセルから順に調べます。
- **訪問済みの印はキューに入れたときに付けます**。各セルはキューに最大1回しか入らないので、容量を通行可能セル数 V にしています。

**なぜ最短経路が求まるか**：BFS は、スタートから移動回数 0 のセル → 1 のセル → 2 のセル → … の順にキューから取り出します。あるセルに最初に到達したときの移動回数が、そのセルまでの最小の移動回数です。**すべての移動コストが等しい（4方向・コスト1）**ので、移動回数の最小 = 経路長の最小になります。

> 移動コストが等しくない場合（Advanced C の斜め移動 √2 など）は、BFS は最小コストを保証しません。

## 7. A\*（エースター）

`search.a_star(grid_map, heuristic=manhattan_distance)`

```text
f(n) = g(n) + h(n)
```

- g(n)：スタートから n までの移動コスト（Core Research では移動回数）
- h(n)：n からゴールまでの**推定**コスト（ヒューリスティック）

f(n) が最小のセルから展開します。優先度付きキューには Python 標準の **`heapq`** を使います（教科書に優先度付きキューのクラスはありません）。

- 要素は `(f, h, 追加順の番号, セル)` です。**f が同じなら h が小さい（ゴールに近い）方、それも同じなら先に追加した方**を先に取り出します。同点時の順序を固定しているので、何度実行しても同じ結果になります。
- `heapq` は要素の優先度を直接変えられないので、より短い経路が見つかったら新しい要素を追加します。**古い要素は、取り出したときに展開済みなら読み飛ばします。**
- 整合的なヒューリスティック（8章）なら、一度展開したセルの g は確定しているので、同じセルを再展開しません。

**最適性の検証**：BFS と A\* が**同じ最短経路長**を返すことをテストで確認しています。最短経路が複数あるときは、経路そのものは BFS と A\* で異なることがあります。

## 8. ヒューリスティック関数

Core Research では**マンハッタン距離**を使います（`search.manhattan_distance`）。

```text
h(n) = |row_n - row_goal| + |col_n - col_goal|
```

| 性質 | 意味 | 4方向・コスト1のマンハッタン距離 |
| --- | --- | --- |
| 許容的（admissible） | h(n) が実際の残りコストを超えない | ○：障害物がなくても、上下左右の移動で最低この回数は必要 |
| 整合的（consistent） | 隣接セル m について h(n) ≤ 1 + h(m) | ○：1回の移動で h は最大1しか変わらない |

許容的なヒューリスティックを使った A\* は最短経路を求めます。h(n) = 0 にすると A\* は BFS（コストが等しい場合）と同じ順序に近い探索になり、h が実際の残りコストに近いほど、展開ノード数は少なくなる傾向があります。他のヒューリスティックとの比較は Advanced B の課題です。

## 9. 経路長と探索ノード数

### 結果の形（3方式で共通）

```python
{
    "found": True,          # ゴールに到達できたか
    "path": [(1, 1), ...],  # スタート → ゴールのセル座標のリスト（到達不能なら None）
    "length": 9,            # 経路長 = 移動回数 = len(path) - 1（到達不能なら None）
    "expanded": 9,          # 展開ノード数
    "order": [(1, 1), ...], # 探索順序（展開したセルを展開した順に並べたもの）
}
```

**経路長はセル数ではなく移動回数**です。5セルからなる経路の経路長は 4 です。

### 展開ノード数の定義

> **スタック・キュー・優先度付きキューから取り出したセルのうち、実際に隣接セルを調べたセルの数。**

- 同じセルを2回以上展開しません（DFS・A\* の古い要素は読み飛ばし、数えません）。
- **ゴール判定は、取り出した直後・隣接セルを調べる前に行います。** ゴールを取り出した時点で探索を終えるので、**ゴール自身は展開ノード数にも探索順序にも含めません**。
- スタート = ゴールの場合、展開ノード数は 0 です（Core Research のマップでは S と G は必ず別のセルです）。
- 到達不能な場合は、スタートから到達できるセルをすべて展開して終わります。

3方式でこの定義をそろえているので、展開ノード数を直接比較できます。

> 注意：BFS のゴール判定を「キューに入れるとき」に行う書き方もあります。その場合は展開ノード数が少なくなります。定義を変えるときは、3方式で同じ定義にそろえてください。

## 10. 理論計算量の比較

通行可能セル数を **V**、移動できる隣接関係（エッジ）の数を **E** とします。

| アルゴリズム | 時間計算量 | 備考 |
| --- | --- | --- |
| DFS | O(V + E) | 各セルを最大1回展開し、各エッジを定数回調べる |
| BFS | O(V + E) | 同上 |
| A\* | 最悪 O((V + E) log V) | 優先度付きキューの push・pop が O(log(キューの長さ))。実際に展開するセルの数はヒューリスティックとマップ構造に依存する |

### グリッドの特徴

4方向移動のグリッドでは、各セルの隣接セルは**最大4個**なので、E ≤ 2V です（各エッジを両端から数えると 4V 以下）。つまり **E は V に比例する規模**で、DFS・BFS の時間計算量はグリッド上では **O(V)** と考えることもできます。

### A\* について

- A\* は**常に BFS より速いとは限りません**。
  - 展開ノード数は少なくなることが多いですが、1回の操作で `heapq` の O(log n) とヒューリスティックの計算が必要です。
  - ゴールへの直線方向が行き止まりになっているマップ（`maze_map.txt` など）では、h が当てにならず、多くのセルを展開することがあります。
  - 到達不能なマップでは、どの方式も到達できるセルをすべて展開します（`blocked_map.txt` では3方式とも 12）。
- 実験では、**展開ノード数と実行時間の両方**を測って比べてください。

### メモリ計算量

| 保存するもの | DFS | BFS | A\* |
| --- | --- | --- | --- |
| 訪問済みセル・親（`parent` の dict） | O(V) | O(V) | O(V)（+ `g` の dict、`closed` の set） |
| スタック／キュー／優先度付きキュー | O(E)（同じセルが複数回入る） | O(V)（各セル最大1回） | O(E)（古い要素が残る） |
| 探索順序（`order`） | O(V) | O(V) | O(V) |

グリッドでは E = O(V) なので、どれも O(V) のメモリを使います。ただし、BFS の「キューの最大の長さ」と DFS の「スタックの最大の長さ」はマップの形によって大きく違います（調べてみましょう）。また `FixedStack`・`FixedQueue` は、最初に容量分のリストを確保する点にも注意してください。

## 11. 教科書との関連

教科書：柴田望洋『新・明解 Pythonで学ぶアルゴリズムとデータ構造（第2版）』

> 教科書には DFS・BFS・A\* の完成済みコードはありません。スタック・キューを使ってグラフ探索を組み立てるのがこの研究の内容です。

### 実際に使用したコード（`textbook/`）

| ファイル | 原本 | 用途 |
| --- | --- | --- |
| `textbook/fixed_stack.py` | 第4章 `chap04/fixed_stack.py`（`FixedStack`） | **DFS のスタック**（`search.dfs`） |
| `textbook/fixed_queue.py` | 第4章 `chap04/fixed_queue.py`（`FixedQueue`） | **BFS の FIFO キュー**（`search.bfs`） |

- `search.py` から `from textbook.fixed_stack import FixedStack` のように**直接 import** しています（Adapter やラッパークラスは作っていません）。
- どちらも**容量固定**です。満杯で push / enque すると `FixedStack.Full` / `FixedQueue.Full`、空で pop / deque すると `Empty` 例外が出ます（データが黙って消えることはありません）。上の 5章・6章で説明した容量を指定しているので、探索中に満杯にはなりません。
- import しても副作用（表示や入力の待ち受け）はありません。
- 教科書のサンプルコードを**そのままコピー**したものです（SHA-256 で原本との一致を確認済み。改行コードも原本どおり CRLF）。**編集しないでください。**

### 利用しなかったコード

| ファイル | 理由 |
| --- | --- |
| 第4章 `chap04/stack.py`（`Stack`）、第5章 `chap05/stack.py`（同じ内容） | `collections.deque(maxlen=...)` を使っており、**満杯のとき例外を出さずに一番古いデータを黙って捨てる**。DFS の途中でセルが失われる危険があるため使用しない |
| 第4章 `chap04/queue.py`（`Queue`） | 同じく `deque(maxlen=...)` で、満杯のとき**先頭（次に取り出すはずのデータ）を黙って捨てる**。BFS のキューとして使うのは誤り |
| 第6章 `chap06/heap_sort.py`、`heap_sort_heapq.py` | ヒープを使ったソート。教科書には優先度付きキューのクラスがないため、A\* では Python 標準の `heapq` を使った。`heap_sort_heapq.py` は `heapq.heappush`・`heappop` の使い方の参考になる |

### 参考にした考え方

- **第3章「探索」**：線形探索・二分探索・ハッシュ法。訪問済みセルの管理に使う Python の `dict`・`set` はハッシュ表なので、「訪問済みか」を平均 O(1) で調べられます（リストで管理すると O(V) かかります）。
- **第5章「再帰的アルゴリズム」**：8王妃問題などのバックトラッキングは、DFS と同じ「深く進んで、だめなら戻る」考え方です。DFS は再帰でも書けますが、大きなマップでは Python の再帰の深さの上限（既定で約1000）を超えるおそれがあるため、このリポジトリではスタックを使っています。

## 14. Core Research：必須課題

すべてのチームが取り組む課題です。

1. **2次元マップを読み込む。**（`grid_map.load_map`）
2. **障害物と通行可能セルを区別する。**（`is_obstacle`、`neighbors`）
3. **DFS で経路を探索する。**
4. **BFS で経路を探索する。**
5. **A\* で経路を探索する。**（マンハッタン距離）
6. **経路長を比較する。**（DFS が最短にならない例を見つけ、理由を説明する）
7. **展開ノード数を比較する。**
8. **探索時間を比較する。**（`time.perf_counter()`、複数回測定。`benchmark.py` の TODO）
9. **探索結果を可視化する。**（`visualization.render_result`）
10. **障害物配置を変更して実験する。**（障害物が少ない／多い、狭い通路、行き止まり、到達不能のマップを自分たちで作る）
11. **結果を表・グラフにまとめる。**
12. **理論計算量と実測結果を考察する。**（V・E と探索時間・展開ノード数の関係）

## 15. Advanced Research：発展課題

必須課題を終えたチームが挑戦する課題です。**Advanced A〜E のうち、チームの能力と時間に応じて1つ以上を選択**してください。すべてを実装する必要はありません。

### Advanced A：障害物密度と探索効率

**目的**：障害物の割合が探索性能に与える影響を調べる。

1. ランダムマップを生成する（`random.Random(seed)` を使い、**乱数シードを記録**する）。
2. 障害物密度を変更する（0%, 10%, 20%, …）。
3. 同じ条件で複数回試行する。
4. 到達可能率を計算する。
5. 経路長を比較する。
6. 展開ノード数を比較する。
7. 探索時間を比較する。

> 障害物密度がある値を超えると、到達可能率が急に下がる現象（パーコレーション）が見られることがあります。

### Advanced B：ヒューリスティック関数の比較

**目的**：A\* のヒューリスティック関数が探索効率に与える影響を調べる。

1. h(n) = 0 を実装する。
2. マンハッタン距離を使う（実装済み）。
3. ユークリッド距離を実装する。
4. 探索ノード数を比較する。
5. 探索時間を比較する。
6. 最短経路が保証される条件を調べる（許容的・整合的とは何か。h を2倍にするとどうなるか）。

`a_star(grid_map, heuristic=自分の関数)` のように、関数 `h(cell, goal)` を渡して試せます。

### Advanced C：8方向移動と移動コスト

**目的**：ロボットが斜め方向にも移動できる場合の経路探索を研究する。

1. 8方向移動を実装する。
2. 水平・垂直移動のコストを 1 とする。
3. 斜め移動のコストを √2 とする。
4. 適切なヒューリスティックを検討する（4方向のマンハッタン距離は、8方向では許容的でなくなる。オクタイル距離などを調べる）。
5. 4方向移動と比較する。
6. 障害物の角をすり抜ける移動（斜め方向の両隣が障害物の場合など）を許すかどうかを定義する。

> **8方向移動では、単純な BFS は最小移動コストを保証しません。** BFS が最小にするのは「移動回数」で、コスト 1 と √2 が混ざると「移動回数が少ない経路」と「コストが小さい経路」が一致しないからです。コストの異なる移動では、Dijkstra 法や A\* を使います。

### Advanced D：動的障害物と経路再探索

**目的**：移動中に障害物が出現した場合の経路変更を研究する。

1. ロボットの現在位置を管理する。
2. 新たな障害物を追加する（`GridMap.rows` は変更できないので、新しいマップを作る）。
3. 既存の経路が通行可能か確認する。
4. 必要に応じて、現在位置から経路を再探索する。
5. 再探索回数を記録する。
6. 総移動距離と計算時間を比較する。

> D\* Lite などの、再探索を効率よく行うアルゴリズムを調べてみるのもよいでしょう。

### Advanced E：実機ロボットへの応用

**目的**：グリッド上の経路探索を、実際の自律移動ロボットに応用するための課題を整理する。

1. ロボットの大きさを考慮する（障害物を「ふくらませる」方法など）。
2. 障害物との安全距離を設定する。
3. 占有格子地図（occupancy grid map）を調査する。
4. センサー（LiDAR・カメラなど）による障害物検出を調査する。
5. 経路計画（どの道を通るか）と運動制御（どう動くか）の違いを整理する。
6. ROS2 のナビゲーション機能（Nav2）との関連を調査する。

**実機制御は必須ではありません。** 調査とまとめ、またはグリッド上でのシミュレーションで構いません。

## 16. 実験条件と評価指標

### 記録すべき実験条件

- PC 環境（CPU、メモリ）、OS、Python のバージョン
- マップ（ファイル名、または生成方法・W・H・障害物の割合・**乱数シード**）
- V（通行可能セル数）・E（隣接関係の数）
- スタートとゴールの座標、その間のマンハッタン距離
- 隣接セルを調べる順序（`grid_map.DIRECTIONS`）
- A\* のヒューリスティック
- 測定の繰り返し回数

### 評価指標

| 指標 | 内容 |
| --- | --- |
| 到達可能か | `found` |
| 経路長 | 移動回数（`length`） |
| 経路のセル数 | `len(path)`（= 経路長 + 1） |
| 展開ノード数 | `expanded`（9章の定義） |
| 探索時間 | `time.perf_counter()` で測定。複数回の平均・中央値 |
| 到達可能率 | 到達可能なマップの数 ÷ 試行したマップの数 |

### 公平な比較の条件

- 同じマップ・同じ障害物配置・同じスタートとゴールを使う
- 同じ移動規則（4方向・コスト1）と、同じ経路長の定義を使う
- 探索時間と経路長は分けて評価する
- 探索時間は複数回測定する（1回だけの値はぶれる。starter.py の Time は参考値）
- 乱数を使う場合は、乱数シードを記録する
- 到達不能なマップは別に集計する（経路長の平均に混ぜない）
